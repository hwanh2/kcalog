# ai-coaching Specification

## Purpose
규칙이 계산한 구조화 신호(오늘 섭취 vs 목표·기간 리포트 신호·유지칼로리·체중 추세)를 LLM에 주입해, 숫자는 우리가 내고 서술만 LLM이 하는 하이브리드로 개인 코칭을 제공하는 능력(차별점 #3)을 규정한다. 하루 1회 캐시하는 오늘의 브리핑과 SSE 스트리밍 대화형 Q&A로 구성하며, LLM 실패 시 규칙 기반 문구로 폴백해 화면이 비지 않게 한다.
## Requirements
### Requirement: 오늘의 브리핑 코칭
시스템은 회원의 구조화 신호(오늘 섭취 vs 목표·주간 리포트 신호·유지칼로리·체중 추세)를 수집해 LLM으로 자연어 코칭(헤드라인·본문·오늘의 추천)을 생성하고 하루 1회 캐시해 제공해야 한다(SHALL). 오늘의 추천은 분류(식단·활동·수분·습관)·제목·설명을 갖는 항목들이어야 한다(MUST). 프롬프트에는 우리가 계산한 숫자만 넣고 LLM은 서술만 하도록 해야 하며(MUST), 신호에 없는 수치를 지어내지 않아야 한다(MUST). 그날 브리핑이 이미 있으면 재생성 없이 캐시를 반환해야 한다(MUST). 감량 변화·목표 달성률·연속일 요약 지표를 함께 반환해야 한다(MUST). 다른 회원의 코칭에는 접근할 수 없어야 한다(MUST).

#### Scenario: 첫 조회 생성·캐시
- **WHEN** 회원이 그날 처음 `GET /api/coach/briefing`을 호출하면
- **THEN** 신호가 수집되어 LLM 코칭이 생성·저장되고 헤드라인·본문·오늘의 추천(분류·제목·설명)과 요약 지표가 반환된다

#### Scenario: 재조회 캐시 반환
- **WHEN** 같은 날 다시 조회하면
- **THEN** 재생성 없이 저장된 브리핑이 그대로 반환된다

#### Scenario: LLM 실패 폴백
- **WHEN** LLM 호출이 실패하거나 빈 응답이면
- **THEN** 규칙 기반 인사이트 문구로 브리핑이 채워져 반환되고 source=FALLBACK으로 표시된다

#### Scenario: 데이터 부족
- **WHEN** 코칭을 낼 기록이 부족하면
- **THEN** 코칭 생성 대신 "데이터가 더 쌓이면" 안내가 반환된다

#### Scenario: 타인 접근 차단
- **WHEN** 인증되지 않은 요청이 브리핑을 조회하면
- **THEN** 접근이 거부된다

### Requirement: 대화형 코칭 Q&A
시스템은 회원이 코치에게 자유 질문을 보내면 회원의 구조화 신호와 최근 대화 맥락을 근거로 LLM 응답을 생성하고, 대화 히스토리를 영속해 제공해야 한다(SHALL). 응답은 SSE로 토큰을 도착 즉시 스트리밍해야 하며(MUST), 완료 시 저장된 코치 메시지로 마무리해야 한다(MUST). 사용자·코치 메시지를 시간순으로 조회할 수 있어야 하며(MUST), 히스토리를 초기화할 수 있어야 한다(MUST). LLM 비용을 방어하기 위해 일일 메시지 상한을 두어야 하며(MUST), 상한 초과 시 응답을 생성하지 않고 안내해야 한다(MUST). LLM 호출 실패는 사용량으로 세지 않아야 한다(MUST NOT). 다른 회원의 대화에는 접근할 수 없어야 한다(MUST).

#### Scenario: 질문·스트리밍 응답
- **WHEN** 회원이 `POST /api/coach/messages`로 질문을 보내면
- **THEN** 사용자 메시지가 저장되고, 개인 데이터를 근거로 생성된 코치 응답이 토큰 단위로 스트리밍된 뒤 저장된 메시지로 마무리된다

#### Scenario: 히스토리 조회
- **WHEN** 회원이 `GET /api/coach/messages`를 호출하면
- **THEN** 자신의 대화가 시간순으로 반환된다

#### Scenario: 초기화
- **WHEN** 회원이 `DELETE /api/coach/messages`를 호출하면
- **THEN** 자신의 대화 히스토리가 모두 삭제된다

#### Scenario: 일일 상한 초과
- **WHEN** 그날 메시지 수가 상한을 초과하면
- **THEN** 코치 응답을 생성하지 않고 상한 안내가 반환된다

#### Scenario: LLM 실패 폴백
- **WHEN** 코치 응답 생성이 실패하면
- **THEN** 폴백 안내 메시지로 스트림이 마무리되고 그 호출은 일일 사용량으로 세지 않는다

#### Scenario: 타인 접근 차단
- **WHEN** 인증되지 않은 요청이 대화를 조회·전송하면
- **THEN** 접근이 거부된다

### Requirement: 홈 코칭 한 줄
시스템은 홈 화면에 오늘 브리핑의 헤드라인을 한 줄로 노출할 수 있게 제공해야 한다(SHALL). 브리핑이 없거나 데이터가 부족하면 한 줄을 비워 홈의 나머지에 영향을 주지 않아야 한다(MUST).

#### Scenario: 홈 한 줄 표시
- **WHEN** 오늘 브리핑이 있는 회원이 홈을 보면
- **THEN** 브리핑 헤드라인이 한 줄로 표시된다

#### Scenario: 브리핑 없음
- **WHEN** 코칭을 낼 데이터가 부족하면
- **THEN** 홈 코칭 한 줄이 비워지고 다른 요소는 정상 표시된다
