# nutrition-correction Specification

## Purpose
사용자가 사진 분석 결과를 정정하고 "이 값 기억하기"를 켜면 그 확정 영양값을 회원별 개인 보정치로 저장(최신값 덮어쓰기)하고, 이후 분석 시 프롬프트 주입(일반화)과 코드 덮어쓰기(정확 재현)로 자동 반영하는 학습형 수정(차별점 #1) 능력을 규정한다.
## Requirements
### Requirement: 정정값 학습 저장
사용자가 분석 결과를 정정하고 "기억하기"를 선택해 저장하면, 시스템은 그 항목의 확정 영양값(kcal·탄·단·지)을 회원별 개인 보정치로 저장해야 한다(SHALL). 매칭 키는 정규화된 음식명이어야 하며(MUST), 같은 음식으로 재정정하면 최신값으로 덮어써야 한다(MUST — last-write-wins). "기억하기"를 선택하지 않은 항목은 보정치로 저장하지 않아야 한다(MUST NOT). 보정치 저장은 식사 저장과 하나의 트랜잭션이어야 한다(MUST) — 식사 저장이 실패하면 보정치 저장도 롤백된다.

#### Scenario: 첫 정정 저장
- **WHEN** 회원이 항목 "김치찌개"의 값을 고치고 "기억하기"를 켠 채 `POST /api/meals`로 저장하면
- **THEN** 그 회원의 개인 보정치에 "김치찌개"의 확정 영양값이 저장된다

#### Scenario: 재정정 덮어쓰기
- **WHEN** 이미 보정치가 있는 음식을 다시 다른 값으로 정정하고 "기억하기"로 저장하면
- **THEN** 기존 보정치가 최신값으로 덮어써진다(평균이 아니다)

#### Scenario: 기억하지 않음
- **WHEN** 회원이 값을 고쳤지만 "기억하기"를 켜지 않고 저장하면
- **THEN** 식사만 저장되고 개인 보정치는 만들어지거나 변경되지 않는다

#### Scenario: 식사 저장 실패 시 보정 롤백
- **WHEN** "기억하기" 저장 중 식사 저장이 실패하면
- **THEN** 보정치 저장도 롤백되어 정합성이 유지된다

### Requirement: 음식명 정규화 매칭
시스템은 개인 보정치를 정규화된 음식명으로 매칭해야 한다(SHALL). 정규화는 모든 공백 제거·영문 소문자화를 포함해야 하며(MUST — 띄어쓰기 불일치 흡수), 표시용 원 이름은 별도로 보존해야 한다(MUST).

#### Scenario: 띄어쓰기 차이 흡수
- **WHEN** 보정치가 "김치찌개"로 저장돼 있고 분석 결과 이름이 " 김치  찌개 "로 오면
- **THEN** 같은 음식으로 매칭된다

### Requirement: 분석 결과에 개인 보정 자동 반영
시스템은 분석 시 회원의 개인 보정치를 반영해야 한다(SHALL). (1) 응답 항목 중 정규화 이름이 보정치와 일치하는 항목은 저장된 보정값으로 정확히 대체하고 "보정됨"으로 표시해야 한다(MUST — 정확 재현). (2) 회원의 보정 이력을 분석 프롬프트에 함께 제공해 유사 음식·다른 양을 개인화할 수 있어야 한다(SHALL). 프롬프트 주입은 토큰·지연 방어를 위해 최근 갱신 상한 개수로 제한해야 하며(MUST), 보정 이력이 없으면 기존 분석과 동일하게 동작해야 한다(MUST).

#### Scenario: 정확 재현(코드 덮어쓰기)
- **WHEN** 보정치가 있는 음식이 분석 결과에 포함되면
- **THEN** 그 항목이 저장된 보정값으로 정확히 대체되고 "보정됨"으로 표시된다(AI 추정값이 달라도)

#### Scenario: 유사 음식 일반화(프롬프트 주입)
- **WHEN** 보정 이력이 프롬프트에 제공된 상태로 분석하면
- **THEN** 정확히 같은 이름이 아닌 음식·다른 양도 사용자 패턴에 맞춰 개인화될 수 있다

#### Scenario: 이력 없음
- **WHEN** 회원의 보정 이력이 하나도 없으면
- **THEN** 프롬프트 주입·덮어쓰기 없이 기존 분석과 동일하게 동작한다

#### Scenario: 주입 상한
- **WHEN** 회원의 보정치가 상한 개수를 초과하면
- **THEN** 최근 갱신 상한 개수만 프롬프트에 주입하고 초과분은 제외한다

### Requirement: 저신뢰 확인 유도
시스템은 분석 전반 신뢰도가 임계값 미만이면 사용자에게 "확인 필요"를 표시해 정정을 유도해야 한다(SHALL). 정정이 곧 개인 보정 학습 데이터가 된다.

#### Scenario: 저신뢰 표시
- **WHEN** 분석 전반 신뢰도가 설정된 임계값 미만이면
- **THEN** 결과에 "확인 필요"가 표시되어 사용자가 값을 확인·정정하도록 유도된다
