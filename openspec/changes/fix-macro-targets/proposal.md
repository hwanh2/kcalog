# 단백질 목표를 체중에 묶는다

## 왜

탄단지 목표가 **칼로리의 고정 비율**로만 정해진다.

```java
// MacroTargetG.java
private static final BigDecimal PROTEIN_RATIO = new BigDecimal("0.3");
```

체중이 식에 들어가지 않는다. 그래서 **칼로리가 커질수록 단백질이 같이 부풀어 오른다.** 73kg 회원이 2700kcal이면 `2700×0.3/4 = 203g`, **2.8 g/kg**이다. 근거 있는 범위(1.6~2.2)를 한참 넘는다.

| 프로필 | 목표 kcal | 단백질 | g/kg |
| --- | ---: | ---: | ---: |
| 남 73/175/30, 보통, 유지 | 2600 | 195g | 2.67 |
| 남 73/175/30, 보통, 증량 | 2900 | 218g | 2.99 |
| 여 55/162/30, 보통, 유지 | 1940 | 146g | 2.65 |
| 여 48/158/25, 가벼움, 유지 | 1620 | 122g | 2.54 |
| 여 62/168/35, 활발, 증량 | 2600 | 195g | **3.15** |

**여성에게 더 나쁘다.** 같은 g/kg이라도 체지방률이 높으면 제지방량 기준으로는 더 높게 나온다. 위 55kg 여성은 제지방 기준 3.7 g/kg이다. 게다가 1940kcal 안에서 146g을 채우려면 칼로리의 30%를 단백질원으로만 써야 해서 현실적으로 못 맞춘다.

**반대 방향으로도 같은 결함이 있다.** 칼로리가 깎이면 단백질도 같이 깎인다. 55kg 여성이 1440kcal로 감량하면 72g(1.31 g/kg)으로, 근손실을 막는 권장선(1.6) 아래로 떨어진다.

원인은 하나다. **단백질이 체중이 아니라 칼로리에 묶여 있다.**

## 무엇을

단백질을 체중으로 자르고, 근육량 목표 여부에 따라 비율을 나눈다.

```
비율      근육량 목표 O → 탄 45 / 단 30 / 지 25
          근육량 목표 X → 탄 55 / 단 20 / 지 25

단백질 =  목표kcal × 단비율 / 4,  체중×1.2 ~ 체중×2.0 으로 자름
지방   =  목표kcal × 0.25 / 9
탄수   =  남은 kcal / 4          (단백질이 잘린 만큼 여기로 흘러감)
```

- **근육량 목표 여부**를 온보딩 목표 단계에서 토글로 받는다. 방향(감량, 유지, 증량) 바로 아래에 두어야 방향은 체중이 어디로 갈지이고 토글은 그 체중의 내용이라는 관계가 읽힌다.
- **지방을 20%에서 25%로 올린다.** 기존 20%는 2700kcal에서 60g(0.82 g/kg)으로 권장 최소선에 걸쳐 있었다.
- 탄수가 많게 느껴지거나 단백질이 많아 보일 때를 위해 **(i) 안내**를 온보딩 결과와 프로필 영양 목표 카드에 둔다.

## 무엇을 하지 않나

- **탄단지를 직접 입력하게 하지 않는다.** 컬럼 3개와 편집 화면이 늘어난다. 지금 필요한 것은 기본값이 말이 되게 만드는 것이다.
- **제지방량을 쓰지 않는다.** 체지방률을 받아야 하는데, 그걸 아는 회원이 적고 온보딩이 길어진다. 체중 기준 상, 하한으로 충분히 잡힌다.
- **기존 회원을 추측해서 채우지 않는다.** `muscle_goal` 기본값은 `false`다. 활동량이 높다고 근육량이 목표라고 단정하면 유산소만 하는 회원을 오분류한다.
- **저장된 값을 바꾸지 않는다.** 탄단지 목표는 조회 시점 파생값이라 기존 기록은 그대로다.
