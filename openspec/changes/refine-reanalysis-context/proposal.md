# 재분석에 직전 맥락을 넘긴다

## 왜

재분석이 사용자의 말을 절반만 듣는다.

지금 `AnalysisJob.reanalyze(note)`는 이렇게 한다.

```java
this.note = note;        // 이전 설명을 덮어쓴다
this.resultJson = null;  // 직전 결과를 지운다
```

그리고 워커는 사진과 방금 적은 설명만 들고 모델을 다시 부른다. 직전에 무엇으로 추정했는지, 지난 회차에 사용자가 뭐라고 했는지는 전달되지 않는다.

**"밥 양 더 줄었어"가 통하지 않는다.** 모델은 직전에 밥을 210g으로 봤다는 사실을 모른 채 사진을 처음부터 다시 본다. 무엇보다 줄이라는 기준이 없으니 결국 다시 찍는 셈이고, 값이 오히려 늘 수도 있다.

**말이 쌓이지 않는다.** 1회차에 "고기는 뺐어", 2회차에 "밥도 적어"라고 하면 앞 설명이 덮여 사라진다. 2회차 결과에 고기가 도로 살아난다. 화면에는 "설명을 덧붙여 다시 분석"이라고 적혀 있는데 실제로는 교체다.

## 무엇을

재분석 요청에 **직전 추정**과 **지금까지 덧붙인 설명 전부**를 함께 보낸다.

- **직전 추정**: 항목별 이름, 섭취량, 영양값을 목록으로 넘기고 "이 값을 기준으로 고치되 언급되지 않은 항목은 그대로 두라"고 지시한다. "더", "조금만", "그거 말고" 같은 상대적인 말이 성립한다.
- **설명 누적**: 최초 설명과 재분석마다 덧붙인 설명을 순서대로 모두 넘긴다. 모델이 지시를 흘려도 다음 회차에 다시 시도된다.

둘 다 필요하다. 직전 추정만 넘기면 반영되지 않은 지시가 결과에 남지 않아 증발하고, 설명만 누적하면 기준점이 없어 "더"가 여전히 공중에 뜬다.

## 무엇을 하지 않나

- **대화형으로 만들지 않는다.** 모델과 여러 턴을 주고받는 구조로 가지 않는다. 재분석은 지금처럼 한 번의 요청이고, 맥락은 그 요청 안에 담는다.
- **재분석 횟수를 늘리지 않는다.** 작업당 2회 그대로다. 맥락이 붙으면 한 번에 맞을 확률이 오르므로 횟수를 늘릴 이유가 오히려 줄어든다.
- **덧붙인 설명을 화면에 보여주지 않는다.** 지금까지 뭐라고 적었는지 목록으로 띄우면 시트가 길어진다. 필요해지면 그때 만든다.
