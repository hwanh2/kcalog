# async-food-analysis 변경

## MODIFIED Requirements

### Requirement: 설명을 덧붙인 재분석

시스템은 완료된 분석 작업에 설명을 덧붙여 다시 분석할 수 있게 해야 한다(SHALL). 재분석은 **기존 작업을 갱신**해야 하며(MUST — 새 작업을 만들지 않는다), 사진이 있으면 저장된 사진을 재사용해야 한다(MUST — 재업로드하지 않는다). 재분석 횟수는 작업당 **최대 2회**로 제한해야 하고(MUST), 각 회차는 일일 분석 횟수를 차감해야 한다(MUST). 사진 없는 작업도 재분석할 수 있어야 한다(SHALL).

재분석 요청에는 **직전 추정 결과를 함께 전달해야 한다**(MUST). 전달하지 않으면 "조금 더 적어요" 같은 상대적인 설명이 기준을 잃는다. 직전 추정은 항목별 이름, 섭취량, 영양값을 포함해야 한다(MUST).

**사용자가 언급하지 않은 항목은 직전 값을 유지하도록 지시해야 한다**(MUST). 한 항목을 고쳐달라는 말에 다른 항목까지 흔들리면, 회차를 거듭할수록 결과를 믿을 수 없게 된다.

지금까지 덧붙인 설명은 **모두 전달해야 한다**(MUST). 최신 설명만 남기고 이전 것을 버려서는 안 된다(MUST NOT) — 모델이 지시를 반영하지 않은 경우 그 지시가 결과에도 남지 않아 영영 사라진다.

#### Scenario: 설명으로 결과 보정
- **WHEN** 회원이 완료된 작업에 "드레싱은 절반만 뿌렸어요"를 덧붙여 재분석하면
- **THEN** 같은 작업이 ANALYZING으로 되돌아가고, 새 결과가 기존 결과를 대체한다

#### Scenario: 직전 값을 기준으로 한 상대적 수정
- **WHEN** 회원이 "밥 양은 이거보다 더 적어요"라고 덧붙여 재분석하면
- **THEN** 직전 추정한 밥의 양이 기준이 되어 그보다 적은 값으로 조정된다

#### Scenario: 언급하지 않은 항목
- **WHEN** 회원이 한 항목에 대해서만 설명을 덧붙이면
- **THEN** 나머지 항목은 직전 추정을 유지한다

#### Scenario: 여러 번 덧붙인 설명
- **WHEN** 회원이 "고기는 뺐어요"로 한 번, "밥도 적어요"로 다시 재분석하면
- **THEN** 두 설명이 모두 반영된다

#### Scenario: 사진 재사용
- **WHEN** 사진이 있는 작업을 재분석하면
- **THEN** 저장된 사진을 그대로 사용하며 사진을 다시 올리지 않는다

#### Scenario: 재분석 상한
- **WHEN** 이미 2회 재분석한 작업을 다시 재분석하려 하면
- **THEN** 거부되고 안내를 반환한다

#### Scenario: 재분석도 횟수 차감
- **WHEN** 회원이 재분석을 요청하면
- **THEN** 일일 분석 횟수가 1 차감되며, 상한을 넘으면 429를 반환하고 재분석하지 않는다

#### Scenario: 타인 작업 재분석 차단
- **WHEN** 다른 회원의 작업을 재분석하려 하면
- **THEN** 거부된다
