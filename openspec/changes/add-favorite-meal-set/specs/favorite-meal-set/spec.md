# favorite-meal-set 변경

## ADDED Requirements

### Requirement: 끼니 세트 저장

시스템은 회원이 **음식 여러 개를 이름 붙인 한 덩어리(세트)로 저장**할 수 있게 해야 한다(SHALL). 세트는 항목별 이름·수량·단위·칼로리·탄단지를 보존해야 한다(MUST).

세트는 **먹은 기록(meal)과 분리해 저장해야 한다**(MUST). 기록을 지워도 세트가 사라져서는 안 되며(MUST NOT), 세트가 하루 섭취 집계·리포트에 더해져서도 안 된다(MUST NOT) — 세트는 먹은 사실이 아니라 틀이다.

세트를 저장해도 **그 안의 음식이 개별 즐겨찾기로 저장되어서는 안 된다**(MUST NOT). 한 번의 저장으로 음식 목록이 불어나면 찾기가 더 어려워진다.

한 세트의 항목은 **한 끼 기록과 같은 개수 상한**을 따라야 한다(MUST) — 상한이 다르면 저장은 되는데 담을 수 없는 세트가 생긴다. 회원당 세트 개수에도 상한이 있어야 한다(MUST).

#### Scenario: 분석 결과를 세트로 저장
- **WHEN** 회원이 사진 분석 결과를 확인하다 "통째로 즐겨찾기"를 누르고 이름을 정해 저장하면
- **THEN** 그 항목들이 한 세트로 저장되고, 개별 음식 즐겨찾기는 늘어나지 않는다

#### Scenario: 저장된 기록을 세트로 저장
- **WHEN** 회원이 이미 기록한 끼니에서 세트 저장을 누르면
- **THEN** 그 기록의 항목들이 세트로 저장된다(사진 없이 담은 조합도 재사용할 수 있다)

#### Scenario: 기록을 지워도 세트는 남는다
- **WHEN** 회원이 세트를 만든 원래 기록을 삭제하면
- **THEN** 세트는 그대로 남아 계속 담을 수 있다

#### Scenario: 세트는 집계에 들어가지 않는다
- **WHEN** 회원이 세트를 저장하기만 하고 담지는 않으면
- **THEN** 그날 섭취 칼로리와 리포트에 아무 변화가 없다

#### Scenario: 항목 개수 상한
- **WHEN** 한 끼 기록의 항목 상한을 넘는 세트를 저장하려 하면
- **THEN** 400을 반환하고 저장하지 않는다

### Requirement: 세트 이름

세트에는 이름이 있어야 한다(MUST). 화면은 **항목에서 만든 기본 이름을 미리 채워야 하며**(SHALL), 회원이 고칠 수 있어야 한다(MUST).

같은 이름의 세트를 다시 저장하면 **기존 세트를 덮어써야 한다**(MUST). 이름 비교는 즐겨찾기 음식과 **같은 정규화 규칙**을 써야 한다(MUST) — 규칙이 갈리면 "저장했는데 또 생긴다"가 된다.

⚠️ 덮어쓰기는 이전 구성을 지우므로, 저장 화면은 **같은 이름이 이미 있다는 것을 미리 알려야 한다**(MUST).

#### Scenario: 기본 이름
- **WHEN** 회원이 항목 5개짜리 분석 결과를 세트로 저장하려 하면
- **THEN** 이름 칸에 항목에서 만든 기본값이 미리 채워져 있고 고칠 수 있다

#### Scenario: 같은 이름 재저장
- **WHEN** 회원이 이미 있는 이름으로 세트를 저장하면
- **THEN** 세트가 하나 더 생기지 않고 기존 세트의 구성이 새 값으로 바뀐다

#### Scenario: 덮어쓰기 예고
- **WHEN** 회원이 입력한 이름이 이미 있는 세트와 같으면
- **THEN** 저장하기 전에 덮어쓴다는 것이 화면에 드러난다

### Requirement: 세트 조회·삭제

시스템은 회원이 자신의 세트 목록을 조회하고 삭제할 수 있게 해야 한다(SHALL). **다른 회원의 세트에는 접근할 수 없어야 한다**(MUST).

목록은 각 세트의 이름과 **합계(칼로리·탄단지)·항목 수**를 담아야 한다(MUST) — 담기 전에 무엇인지 알 수 있어야 한다.

#### Scenario: 세트 목록
- **WHEN** 회원이 세트 목록을 조회하면
- **THEN** 각 세트의 이름·항목 수·합계 칼로리와 탄단지가 함께 온다

#### Scenario: 남의 세트 삭제 시도
- **WHEN** 회원이 다른 회원의 세트를 지우려 하면
- **THEN** 거부되고 세트는 그대로 남는다

### Requirement: 세트로 기록하기

회원은 세트를 골라 그 끼니의 기록으로 담을 수 있어야 한다(SHALL). 담기 전에 **든 음식을 보여주고 고칠 수 있어야 한다**(MUST) — 항목을 빼거나 수량을 조절할 수 있어야 한다(MUST). 세트는 틀이지 그날 먹은 양이 아니다.

담아서 만들어지는 것은 **평범한 끼니 기록**이어야 한다(MUST). 세트에서 왔다는 이유로 다른 방식으로 저장되어서는 안 된다(MUST NOT).

세트를 담아도 **세트 자체는 바뀌지 않아야 한다**(MUST NOT) — 그날 밥을 반만 먹었다고 틀이 반으로 줄면 안 된다.

#### Scenario: 세트로 담기
- **WHEN** 회원이 세트를 누르고 항목을 확인한 뒤 담으면
- **THEN** 선택된 끼니에 그 항목들로 기록 하나가 만들어진다

#### Scenario: 일부만 담기
- **WHEN** 회원이 세트에서 항목 하나를 빼고 다른 하나의 수량을 줄여 담으면
- **THEN** 고친 대로 기록되고, 세트의 원래 구성은 그대로 남는다

### Requirement: 세트는 음식 목록과 구분해 보여준다

세트는 **개별 음식 목록과 섞이지 않아야 한다**(MUST). 담기는 단위가 다르므로 한 줄로 나란히 놓으면 무엇이 한 끼인지 알 수 없다.

#### Scenario: 즐겨찾기 화면
- **WHEN** 회원이 즐겨찾기를 열면
- **THEN** 세트와 개별 음식이 구분된 자리에 각각 보인다

#### Scenario: 세트가 하나도 없을 때
- **WHEN** 아직 세트를 만들지 않은 회원이 즐겨찾기를 열면
- **THEN** 세트 자리가 빈 채로 남지 않고, 음식 목록이 화면을 차지한다
