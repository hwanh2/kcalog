# fix-record-ux

## Why

`improve-ui-accessibility`를 마치고 남은 화면을 훑다가, **접근성이 아니라 신뢰성에 구멍이 있다**는 걸 알게 됐다.

**실패가 조용히 사라진다.** 화면에 `useMutation`이 14개인데 `onError`는 **0개**고, 실패를 알려주는 곳은 2곳뿐이다. 즐겨찾기 저장·해제, 기록 삭제·수정, 프로필 저장, 체중 기록은 **실패해도 화면에 아무 일도 일어나지 않는다.** 지하철에서 즐겨찾기를 지웠는데 요청이 실패하면 ★이 그대로인데 이유를 알 수 없다. 사용자는 앱이 고장 났다고 생각하거나, 더 나쁘게는 저장됐다고 믿는다.

**저장에 실패하면 입력한 내용이 사라진다.** `RecordsPage`는 "잠시 후 다시 시도해주세요"만 띄우는데, 그 시점에 담기 시트는 이미 닫혀 항목이 날아갔다. 처음부터 다시 입력해야 하고, AI 분석으로 담은 것이면 **일일 분석 횟수까지 함께 날린다.**

**기록 삭제에 확인이 없다.** 휴지통을 누르면 즉시 지워지고 되돌릴 수 없다. 그 버튼은 탭 대상이 28px이고 바로 옆이 수정 영역이라, 고치려다 지우기 쉽다. 앱에서 유일하게 데이터가 사라지는 동작인데 앱 전체에서 확인 절차가 있는 곳은 재분석 덮어쓰기 하나뿐이다.

여기에 눈에 보이는 거친 부분이 더 있다 — 사진이 로드되며 아래 내용이 밀리고(CLS), 숫자가 세로로 안 맞고, 목록 로딩이 맨 텍스트 한 줄이다.

## What Changes

- **기록 삭제에 확인 시트** — 브라우저 기본 `confirm` 대신 `Sheet` 기반 확인을 쓴다. 이미 만들어 둔 시트라 Esc·포커스 가둠·안전 영역이 따라온다. 삭제 버튼의 탭 대상도 44px로 넓힌다.
- **실패를 빠짐없이 알린다** — 모든 뮤테이션에 실패 안내를 붙인다. 안내는 `role="alert"` + 오류 색이며, 무엇이 실패했고 다음에 무엇을 하면 되는지 말한다.
- **저장 실패 시 담은 내용을 지키고 재시도한다** — 실패하면 항목을 버리지 않고 들고 있다가 "다시 시도" 한 번으로 같은 요청을 보낸다. AI 분석 결과도 그대로 살린다.
- **즐겨찾기 성공 문구를 없앤다** — ★이 채워지고 비워지는 것 자체가 결과다. 문구가 뜨면 시선이 목록에서 벗어나고, 자동으로 사라지지도 않아 화면에 남는다. **성공은 조용히, 실패만 알린다.**
- **사진에 자리를 미리 잡는다** — `<img>` 4곳에 종횡비를 줘서 로드 순간 아래 내용이 밀리지 않게 한다.
- **숫자를 자릿수로 정렬한다** — kcal·매크로처럼 세로로 쌓여 비교되는 숫자에 `tabular-nums`를 준다.
- **목록 로딩을 스켈레톤으로** — "불러오는 중…" 텍스트 대신 들어설 자리를 보여준다. 분석 화면이 이미 쓰는 방식이다.
- **수정할 수 있음을 드러낸다** — 기록 카드 본문이 통째로 수정 버튼인데 아무 단서가 없다. 누를 수 있는 면으로 보이게 한다.
- **음식 목록의 중복을 없앤다** — 카탈로그에 있는 음식을 즐겨찾기에 저장하면 통합 목록에 **사본과 원본이 둘 다** 나온다(★도 양쪽에 채워져 어느 것이 내 값인지 알 수 없다). 서버가 목록을 만들 때 이름이 겹치는 카탈로그 항목을 빼고, 회원이 저장한 값을 남긴다.

## Impact

- Affected specs: `ui-feedback` (신규) — 확인·성공/실패 피드백·로딩·레이아웃 안정성을 **화면 공통 규범** 하나로 모은다. `meal-logging`은 건드리지 않는다: 거기 있는 "기록 삭제"는 서버 동작(사진까지 지운다)이고, 이번에 더하는 것은 그 앞단의 화면 규약이라 층이 다르다. `ui-accessibility`와 같은 자리에 두어 앞으로 만들 화면에도 자동으로 적용되게 한다.
- Affected specs: `food-catalog` (수정 — 통합 목록의 중복 제거)
- Affected code (프론트): `features/meal/MealCard.tsx`, `pages/RecordsPage.tsx`, `features/food/AddFoodPanel.tsx`, `features/meal/{AnalysisResultSheet,PhotoOverlay,AiRecordPanel,AnalyzingView}.tsx`, `features/weight/WeightPanel.tsx`, `features/tdee/TdeeCard.tsx`, `pages/CoachPage.tsx`, `ui/`(확인 시트·오류 안내·스켈레톤 신설), `lib/useSafeMutation.ts`
- Affected code (백엔드): `FoodService.findAll` — 즐겨찾기와 이름이 겹치는 카탈로그 항목 제외
- 마이그레이션: 없음
- 스코프 밖:
  - **썸네일 지연 로드** — `AuthImage`가 fetch→blob으로 가져오는 구조라 `loading="lazy"`가 통하지 않고 `IntersectionObserver`를 직접 붙여야 한다. 별도로 다룬다.
  - **지난 날짜 기록 수정** — 음식기록 탭을 "오늘 담는 화면"으로 설계한 결정과 얽혀 있어 화면 구조부터 다시 봐야 한다.
  - **실행취소(undo) 토스트** — 삭제 확인의 대안으로 검토했으나 토스트 기반과 삭제 지연 처리가 필요해 이번 범위에서 뺀다.
