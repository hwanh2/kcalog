## Why

현재 식사 분석은 사진 한 장 → **총량(총 칼로리·탄단지) 하나**만 낸다(add-meal-weight-tracking 그룹 4~5). 사용자는 "사진을 찍으면 각 음식이 개별로 인식되어, 사진 위에 음식명·성분이 표시되고, 아래에 합계가 나오며, 각각 수정"하는 경험을 원한다. 이는 기존에 1차 비범위로 미뤄둔 **음식별 아이템 분석(meal_item)**을 도입하는 변경이다.

이 change는 총량 흐름을 토대로 **음식별 분석 + 사진 위 좌표 오버레이 + 음식별 저장**으로 확장한다.

## What Changes

- **분석 출력 재설계**: AI가 총량 하나가 아니라 **음식별 항목 배열**(이름·칼로리·탄단지·사진 내 위치 박스)과 **합계**를 반환한다. 프롬프트·구조화 출력 스키마 전면 수정.
- **사진 위 오버레이 UI**: 촬영/선택한 사진을 확인 화면에 띄우고, 각 음식 위치에 박스+라벨(이름·성분)을 그린다. 사진은 **저장하지 않고** 촬영 세션의 브라우저 메모리에서만 사용한다(위치 박스도 저장 안 함).
- **좌표 부정확 대비 폴백**: 비전 모델의 위치 정확도 한계를 고려해, 박스가 없거나 신뢰도가 낮으면 **목록형(사진 아래 음식 카드 목록)으로 자동 전환**한다.
- **음식별 수정**: 각 음식의 이름·영양값 수정, 항목 추가·삭제. 합계는 항목 합으로 **자동 재계산**.
- **음식별 저장(meal_item)**: 확정 시 meal(합계) + meal_item(음식별)로 저장. meal의 total_*는 항목 합계로 재계산(비정규화). 위치 박스는 사진 미저장이므로 persist하지 않는다.
- **기록 조회·수정**: 기록 탭에서 저장된 식사를 **음식별 목록**으로 조회·수정·삭제.
- **eval 확장**: 음식별 인식·좌표 정확도를 초기에 실측해 오버레이 유지/목록형 폴백을 판단.

명시적 비범위: 사진 영구 저장(스토리지), 음식 DB 검색 입력, 바코드.

## Capabilities

### New Capabilities
- `meal-item-analysis`: 음식별 AI 분석(항목 배열+위치 박스+합계), 사진 위 오버레이 UI와 목록형 폴백, 음식별 수정·추가·삭제와 합계 자동 재계산
- `meal-item-storage`: meal_item(음식별) 저장, meal 합계 재계산, 음식별 조회·수정·삭제

### Modified Capabilities
- (없음 — meal-logging 스펙은 아직 아카이브 전이라 정식 delta 대상이 아니다. 총량 경로를 대체·확장하는 관계는 design.md에 기록하고, 신규 capability의 ADDED 요구사항으로 표현한다)

## Impact

- **백엔드**: Flyway `V6__meal_item.sql`(meal_item 테이블). 분석 스키마·프롬프트(items[]+box+total) 재작성. `POST /api/meals`가 items를 받아 meal+meal_item 저장, 합계 재계산. `GET/PATCH /api/meals`가 items 포함. meal 엔티티에 items 연관(애그리거트 내 객체 참조).
- **프론트**: 확인 화면을 오버레이(사진+박스+라벨)로 재작성, 목록형 폴백, 음식별 편집·추가·삭제·합계 재계산. 기록 탭 음식별 표시. 총량 확인 화면은 대체된다.
- **eval**: 음식별·좌표 정확도 채점 추가.
- **비용/성능**: 항목 분해로 출력 토큰이 늘어 회당 비용 소폭 증가(여전히 저렴). 일일 제한은 그대로.
