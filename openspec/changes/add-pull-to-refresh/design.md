# 설계 — 당겨서 새로고침

## D1. 셸에 한 번만 둔다

화면마다 붙이면 두 가지가 어긋난다. 새로 만드는 탭에서 **빠뜨리고**, 무엇을 다시 부를지도 화면마다 달리 적게 된다.

셸에 두고 `refetchQueries({ type: 'active' })`를 부르면 그 판단 자체가 없어진다 — **지금 화면이 실제로 구독 중인 조회**가 곧 다시 부를 대상이다. 화면이 늘어도 손댈 곳이 없다.

대가: 셸이 `QueryClient`를 쓰게 되어 `renderWithAuth`(공통 테스트 렌더)에도 provider가 필요해졌다. 실제 `App.tsx`도 셸 전체를 감싸고 있으므로 **테스트가 실제 구조에 가까워진 것**이지 우회가 아니다.

## D2. 본문은 옮기지 않는다 — 표시만 내려온다

손끝을 따라 본문이 함께 내려오면 더 붙어 보인다. 그런데 **`transform`이 걸린 요소는 `position: fixed` 자식의 기준이 된다.**

```
main { transform: translateY(40px) }   ← 당기는 동안
  └ 바텀시트 (fixed inset-0)            ← 화면이 아니라 main 기준으로 뜬다
```

당기는 중에는 시트가 열려 있지 않지만, 새로고침이 도는 동안(표시가 세워져 있는 동안)에는 열릴 수 있다. **그 한 번을 위해 모든 시트를 위험에 두지 않는다.** 표시 하나만 내려와도 당기고 있다는 것은 충분히 읽힌다.

## D3. 저항과 임계점

| | 값 | 이유 |
| --- | --- | --- |
| 저항 | 0.5 | 손가락 거리를 그대로 따라가면 화면이 훌렁 내려간다 |
| 임계점 | 64px | 실수로 넘기지 않을 만큼 멀고, 한 손으로 닿을 만큼 가깝다 |
| 최대 | 96px | 더 끌어도 늘어나지 않아 "이미 충분하다"가 손에 읽힌다 |
| 도는 중 자리 | 52px | 임계점(64)에 그대로 두면 표시가 **첫 카드 위에 얹혀** 무엇을 불러오는지 가린다 |

되는 지점을 넘기면 화살표가 뒤집힌다 — 문구 없이 "이제 놓으세요"를 말한다.

## D4. 시작하지 않아야 할 세 경우

`touchstart`에서 가른다. 시작한 뒤에 취소하면 이미 스크롤이 한 번 튄 뒤다.

1. **문서가 맨 위가 아닐 때** (`window.scrollY > 0`) — 목록 중간에서 당기는 것은 스크롤이다
2. **시트 안** (`role="dialog"` 조상) — 시트가 떠 있으면 뒤 문서는 맨 위지만, 뒤 화면을 새로고침할 이유는 없다
3. **자기 스크롤이 내려간 영역 안** — AI PT 대화처럼 안쪽 스크롤을 가진 곳은 그쪽이 먼저다

2·3은 터치 지점에서 조상을 거슬러 올라가며 본다. 셸이 자식 화면의 구조를 알 필요가 없어진다.

## D5. `passive: false`가 필요한 곳은 `touchmove` 하나

`preventDefault`를 해야 iOS의 고무줄 튕김과 겹치지 않는다. 기본값(`passive: true`)이면 `preventDefault`가 조용히 무시된다.

`touchstart`는 `passive: true`로 둔다 — 거기서는 막을 것이 없고, passive가 스크롤 시작을 빠르게 한다.

## D6. 제스처 값은 ref, 그린 것만 state

리스너는 한 번만 붙고(`[targetRef]`), 그 안에서 최신 값을 읽어야 한다. 그래서 진행 중 값(시작 y, 당긴 거리, 새로고침 중 여부, 콜백)은 ref에 둔다. `state`는 **화면에 그려지는 거리**만 들고 있다.

콜백까지 ref로 둔 이유: `onRefresh`가 매 렌더 새 함수라 의존성에 넣으면 **제스처 도중에 리스너가 다시 붙는다.**

## D7. 터치 전용으로 둔다

마우스·키보드로는 새로고침할 수 없다. 데스크톱 브라우저에는 주소창 새로고침이 있어 이 수단이 필요 없고, **없는 문제를 위해 두 벌을 만들지 않는다.**

도는 동안에는 `role="status"`로 "새로고침 중"을 알린다 — 보이는 표시는 장식(`aria-hidden`)이라 그것만으로는 화면 낭독기에 아무것도 전해지지 않는다.
