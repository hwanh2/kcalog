# weekly-report (delta)

## ADDED Requirements

### Requirement: 기간 리포트 조회
시스템은 주간·월간·총 기간을 버킷으로 엮어 목표 달성 요약·탄단지 분포·TDEE 변화·인사이트를 계산해 제공해야 한다(SHALL). 기간을 지정할 수 있어야 하며 생략 시 주간으로 본다(MUST). 버킷은 주간=요일별·월간=일별·총=월별이어야 한다(MUST). 값은 조회 시 계산하며 별도 영속화하지 않아야 한다(MUST). 다른 회원의 리포트에는 접근할 수 없어야 한다(MUST).

#### Scenario: 주간 리포트
- **WHEN** 회원이 `GET /api/reports?period=WEEK`를 호출하면
- **THEN** 이번 주 요일별 버킷과 달성 요약·분포·TDEE 시리즈·인사이트가 반환된다

#### Scenario: 월간·총 기간
- **WHEN** 회원이 `period=MONTH` 또는 `TOTAL`로 조회하면
- **THEN** 각각 일별·월별 버킷으로 집계된 리포트가 반환된다

### Requirement: 목표 달성 요약
시스템은 주간 목표 달성 요약을 제공해야 한다(SHALL). 하루 총섭취를 기준으로 감량 목표면 `섭취 ≤ 목표`, 그 외에는 목표 근접 밴드(±10%) 안일 때 달성으로 세어야 한다(MUST). 달성일 수·기록일 수·기록일 평균 섭취·목표를 포함해야 하며(MUST), 목표가 없으면 달성 판정은 비운다(MUST).

#### Scenario: 달성일 집계
- **WHEN** 목표가 있는 회원의 주간을 조회하면
- **THEN** 규칙에 따라 달성일 수와 평균 섭취·목표가 반환된다

#### Scenario: 목표 없음
- **WHEN** 목표가 설정되지 않은 회원의 주간을 조회하면
- **THEN** 달성 판정 없이 평균 섭취·분포만 반환된다

### Requirement: 탄단지 분포
시스템은 버킷별 일 평균 탄단지(g)와 기간 평균·칼로리 비율(%)·목표 대비를 제공해야 한다(SHALL). 비율은 탄4·단4·지9 kcal 환산으로 계산해야 한다(MUST). 버킷은 스택 막대로 표현할 수 있게 버킷별 탄·단·지를 포함해야 한다(MUST).

#### Scenario: 분포 계산
- **WHEN** 기록이 있는 기간을 조회하면
- **THEN** 버킷별 일 평균 탄단지와 기간 평균 g·칼로리 비율·목표 g가 반환된다

### Requirement: TDEE 변화 시리즈
시스템은 주간 각 날짜의 유지칼로리(TDEE)를 계산해 시리즈로 제공해야 한다(SHALL). 각 점은 날짜·유지칼로리·출처(실측/공식)를 포함해야 하며(MUST), 그 날짜 기준 트레일링 창으로 재계산해야 한다(MUST).

#### Scenario: 주간 TDEE 시리즈
- **WHEN** 회원이 주간을 조회하면
- **THEN** 주간 날짜별 TDEE(출처 포함)가 시리즈로 반환된다

### Requirement: 규칙 기반 인사이트
시스템은 주간 신호를 계산하고 심각도로 랭킹해 상위 인사이트를 문구로 제공해야 한다(SHALL). 인사이트는 결정적이어야 하며 외부 LLM에 의존하지 않아야 한다(MUST). 데이터가 부족하면 인사이트 대신 안내를 반환해야 한다(MUST).

#### Scenario: 상위 인사이트
- **WHEN** 충분한 기록이 있는 주간을 조회하면
- **THEN** 계산된 신호 중 심각도 상위 항목이 문구로 반환된다

#### Scenario: 데이터 부족
- **WHEN** 인사이트를 낼 기록이 부족하면
- **THEN** 인사이트 대신 "데이터가 더 쌓이면" 안내를 반환한다
