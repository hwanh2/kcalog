# app-shell 변경

## ADDED Requirements

### Requirement: 앱 헤더 표기

상단 헤더는 **서비스명만** 보여야 한다(MUST). 서비스명은 `kcalog`다(AGENTS.md 확정). 부제·설명 문구를 함께 두어서는 안 된다(MUST NOT) — 모든 화면 맨 위에 상시로 붙어 있어 본문이 그만큼 밀린다.

#### Scenario: 헤더 표기
- **WHEN** 회원이 어느 탭을 보든
- **THEN** 헤더에는 `kcalog`와 프로필 진입 버튼만 있고, 설명 문구는 없다

### Requirement: 화면 첫 요소의 위 여백

각 탭 화면의 **첫 요소는 스스로 위 여백을 갖지 않아야 한다**(MUST NOT). 셸이 이미 본문 위쪽 여백을 준다 — 화면이 또 얹으면 그 화면만 아래로 밀려 탭을 옮길 때마다 시작 위치가 흔들린다.

#### Scenario: 탭 이동 시 시작 위치
- **WHEN** 회원이 홈·음식기록·체중·리포트·AI PT를 오가면
- **THEN** 모든 탭에서 첫 요소가 같은 높이에서 시작한다

### Requirement: 음식기록 탭의 헤더

음식기록 탭에서는 **앱 헤더를 노출하지 않아야 한다**(MUST NOT). 그 화면은 기록 목록·합계·추가 영역을 한 화면에 담아 세로 공간이 가장 모자란데, 서비스명 줄이 맨 위를 상시로 차지하면 본문이 그만큼 밀린다. 그 자리는 **끼니 선택이 대신해야 한다**(SHALL).

헤더를 감춰도 **다른 화면으로 나갈 길이 막혀서는 안 된다**(MUST NOT) — 하단 내비는 그대로 남는다.

#### Scenario: 음식기록 탭 진입
- **WHEN** 회원이 음식기록 탭을 열면
- **THEN** 서비스명 헤더 없이 끼니 선택이 첫 줄에 오고, 하단 내비로 다른 탭에 갈 수 있다

#### Scenario: 다른 탭
- **WHEN** 회원이 홈·체중·리포트·AI PT를 열면
- **THEN** 헤더와 프로필 진입 버튼이 그대로 보인다

### Requirement: 화면 전환 시 스크롤 위치

다른 화면으로 옮기면 **맨 위에서 시작해야 한다**(MUST). 브라우저는 문서 스크롤을 그대로 두므로, 긴 화면을 내려보다 이동하면 도착한 화면이 중간에서 시작해 이미 지나간 화면처럼 보인다.

#### Scenario: 긴 화면에서 이동
- **WHEN** 회원이 홈을 아래로 내려본 뒤 다른 화면으로 이동하면
- **THEN** 도착한 화면이 맨 위에서 시작한다

### Requirement: 하단 내비와 본문이 겹치지 않는다

본문 아래 여백은 **하단 내비 높이와 기기 안전 영역을 함께** 반영해야 한다(MUST). 고정값만 두면 `env(safe-area-inset-bottom)`이 있는 기기에서 내비가 그만큼 두꺼워져 마지막 내용이 가려진다.

#### Scenario: 노치 기기의 목록 끝
- **WHEN** 회원이 안전 영역이 있는 기기에서 화면 맨 아래까지 내리면
- **THEN** 마지막 카드가 하단 내비에 가리지 않고 온전히 보인다

### Requirement: 화면 확대·축소 잠금

앱은 **핀치 확대·축소와 더블탭 확대를 막아야 한다**(MUST). 고정 폭 모바일 레이아웃이라 확대·축소는 레이아웃을 깨뜨린 채로 남긴다.

잠금은 **홈 화면에서 실행한 경우와 브라우저 탭으로 연 경우 모두**에서 동작해야 한다(MUST) — iOS Safari는 viewport 메타의 `user-scalable=no`를 무시하므로 메타 하나로는 브라우저 탭에서 열리지 않는다.

⚠️ 이 요구사항은 **WCAG 2.1 AA 1.4.4(Resize text)와 상충한다.** 확대에 의존하는 회원의 수단을 없애므로, 본문 글자 크기를 조절할 다른 수단이 생기면 이 잠금을 재검토해야 한다(SHOULD).

#### Scenario: 핀치 확대
- **WHEN** 회원이 모바일에서 두 손가락으로 화면을 벌리거나 좁히면
- **THEN** 화면 배율이 바뀌지 않는다

#### Scenario: 더블탭 확대
- **WHEN** 회원이 화면을 두 번 빠르게 두드리면
- **THEN** 확대되지 않고, 그 자리의 버튼이 반응한다
