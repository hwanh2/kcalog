# deployment (delta)

## ADDED Requirements

### Requirement: 운영 시크릿 필수 주입
운영 프로파일은 DB 접속 정보, JWT 서명 키, OAuth 자격증명, LLM API 키, 사진 스토리지 접근 정보를 환경변수로만 받아야 하며 기본값을 가져서는 안 된다(MUST NOT). 하나라도 주입되지 않으면 애플리케이션은 기동에 실패해야 한다(MUST) — 안전하지 않은 기본값으로 동작하는 것보다 뜨지 않는 편이 낫다.

#### Scenario: 시크릿 누락 시 기동 실패
- **WHEN** 운영 프로파일로 기동하는데 필수 환경변수가 비어 있으면
- **THEN** 애플리케이션이 기동에 실패하고 어떤 요청도 처리하지 않는다

#### Scenario: 개발 기본값이 운영에 새지 않음
- **WHEN** 운영 프로파일로 기동하면
- **THEN** 로컬 개발용 기본 서명 키·자격증명은 사용되지 않는다

### Requirement: 헬스체크 공개
시스템은 인증 없이 조회할 수 있는 헬스체크 엔드포인트를 제공해야 한다(SHALL). 응답은 데이터베이스 연결 가능 여부를 반영해야 하며(MUST), 내부 구성 상세(환경변수, 설정값, 의존 컴포넌트 목록)를 노출해서는 안 된다(MUST NOT).

#### Scenario: 미인증 헬스체크
- **WHEN** 인증 토큰 없이 헬스체크를 요청하면
- **THEN** 401이 아니라 서비스 상태가 담긴 200 응답을 받는다

#### Scenario: DB 장애 반영
- **WHEN** 데이터베이스에 연결할 수 없는 상태에서 헬스체크를 요청하면
- **THEN** 정상이 아닌 상태를 응답해 배포·감시 도구가 실패를 인지할 수 있다

#### Scenario: 상세 정보 비노출
- **WHEN** 헬스체크 응답을 확인하면
- **THEN** 개별 컴포넌트의 상세 진단 정보가 포함되지 않는다

### Requirement: 교차 출처 요청 제어
프론트엔드와 API가 다른 출처에서 서비스되므로, 시스템은 허용 목록에 있는 출처의 교차 출처 요청만 허용해야 한다(MUST). 허용된 출처에 대해서는 자격증명(쿠키) 포함 요청과 `Authorization` 헤더를 허용해야 한다(MUST). 허용 출처는 환경변수로 주입받아야 하며(SHALL), 모든 출처를 여는 와일드카드를 사용해서는 안 된다(MUST NOT).

#### Scenario: 허용된 출처의 요청
- **WHEN** 허용 목록에 등록된 프론트엔드 출처에서 `Authorization` 헤더를 담아 API를 호출하면
- **THEN** 요청이 처리되고 응답에 해당 출처를 허용하는 헤더가 포함된다

#### Scenario: 허용되지 않은 출처의 요청
- **WHEN** 허용 목록에 없는 출처에서 API를 호출하면
- **THEN** 응답에 그 출처를 허용하는 헤더가 포함되지 않아 브라우저가 결과를 차단한다

#### Scenario: 자격증명 포함 요청
- **WHEN** 허용된 출처에서 refresh 토큰 쿠키를 담아 토큰 재발급을 요청하면
- **THEN** 쿠키가 전달되어 재발급이 성공한다

### Requirement: 리버스 프록시 뒤에서의 외부 주소 인식
시스템은 리버스 프록시가 전달한 프로토콜·호스트 헤더를 반영해 외부에 노출할 절대 URL을 만들어야 한다(MUST). 프록시가 TLS를 종료하더라도 생성되는 URL은 `https`여야 한다(MUST).

#### Scenario: OAuth 리다이렉트 URI 생성
- **WHEN** HTTPS로 들어온 요청이 프록시를 거쳐 평문으로 애플리케이션에 도달한 상태에서 소셜 로그인을 시작하면
- **THEN** 인증 제공자에게 전달되는 리다이렉트 URI가 `https` 주소로 생성되어 등록된 값과 일치한다

### Requirement: 단일 페이지 앱 경로 폴백
프론트엔드 호스팅은 정적 자산이 아닌 모든 경로 요청에 대해 앱 진입 문서를 반환해야 한다(MUST). 클라이언트 라우팅을 쓰므로 이것이 없으면 링크 직접 진입과 새로고침이 실패한다.

#### Scenario: 하위 경로 직접 진입
- **WHEN** 사용자가 앱 내부 경로 URL로 직접 접속하거나 그 화면에서 새로고침하면
- **THEN** 404가 아니라 앱이 로드되고 해당 화면이 표시된다
