# meal-item-analysis 변경

## ADDED Requirements

### Requirement: 저장 대상 끼니 변경

분석 결과 확인 화면은 **그 결과를 어느 끼니로 저장할지 그 자리에서 바꿀 수 있어야 한다**(MUST). 끼니를 고치려고 화면을 닫고 분석을 다시 하게 해서는 안 된다(MUST NOT).

끼니 선택은 **저장 동작 바로 옆에 붙어 한 문장처럼 읽혀야 한다**(SHALL) — "○○에 기록하기"에서 ○○만 고를 수 있는 형태다. 여기서 고른 끼니는 **이 화면을 연 쪽의 선택과 같은 값을 가리켜야 한다**(MUST) — 두 곳이 서로 다른 끼니를 들고 있으면 안 된다.

모바일에서는 **OS가 제공하는 선택기**로 열려야 한다(SHALL). 끼니를 고르려고 이 화면 위에 또 다른 시트를 쌓아서는 안 된다(MUST NOT) — 항목 편집·즐겨찾기 시트가 이미 그 위에 열린다.

#### Scenario: 결과 화면에서 끼니 변경
- **WHEN** 회원이 분석 결과를 확인하다 끼니가 잘못된 걸 발견하고 다른 끼니를 고르면
- **THEN** 고른 끼니가 저장 동작 옆에 그대로 보이고, 저장하면 그 끼니의 기록으로 들어간다

#### Scenario: 선택이 뒤 화면과 이어진다
- **WHEN** 회원이 결과 화면에서 끼니를 바꾸고 저장을 마치면
- **THEN** 음식기록 탭의 끼니 선택도 같은 끼니를 가리킨다

### Requirement: 사진 위 배지는 사진 안에 머문다

음식별 배지는 **사진 경계를 넘어가지 않아야 한다**(MUST). 넘어간 부분은 화면에서 잘려 **이름과 값을 읽을 수 없다.**

배지끼리 겹치는 것은 허용한다(SHALL) — 음식이 붙어 있으면 배지도 붙는다. 잘리는 것과 겹치는 것은 다르다.

#### Scenario: 사진 가장자리의 음식
- **WHEN** 사진 왼쪽·오른쪽 끝에 있는 음식의 배지가 그려지면
- **THEN** 배지 전체가 사진 안에 들어와 이름과 탄단지를 다 읽을 수 있다

#### Scenario: 이름이 긴 음식
- **WHEN** "고추장/채소무침 추정"처럼 이름이 긴 항목의 배지가 그려지면
- **THEN** 배지가 사진 폭을 넘지 않고, 필요하면 이름이 줄바꿈된다
