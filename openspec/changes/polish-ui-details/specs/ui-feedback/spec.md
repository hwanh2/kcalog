# ui-feedback 변경

## ADDED Requirements

### Requirement: 화면 전체가 기다릴 때도 앱의 화면을 보여준다

화면 전체를 차지하는 대기(인증 확인·로그인 처리처럼 아무것도 그릴 수 없는 상태)는 **앱의 화면으로 보여야 한다**(MUST). 스타일 없는 텍스트 한 줄을 두어서는 안 된다(MUST NOT) — 앱을 열 때 가장 먼저 보이는 화면이다.

대기 화면은 무엇을 기다리는지 **글로 밝혀야 하며**(MUST), 그 글은 눈에 보여야 한다(MUST). 움직임에만 의존해서는 안 된다(MUST NOT) — 모션 축소 설정에서는 움직임이 멈추므로 글이 유일한 단서가 된다. 스크린리더에도 알려야 한다(MUST).

같은 성격의 대기는 **같은 화면을 써야 한다**(SHALL).

#### Scenario: 앱 진입 시 인증 확인
- **WHEN** 회원이 앱을 열어 인증 확인이 끝나기를 기다리면
- **THEN** 앱 로고와 함께 대기 중임을 알리는 화면이 보인다

#### Scenario: 모션 축소 설정
- **WHEN** 모션 축소를 켠 회원이 같은 화면을 보면
- **THEN** 움직임이 멈춘 상태에서도 무엇을 기다리는지 글로 읽을 수 있다

### Requirement: 단계가 넘어가도 같은 것은 같은 크기로

여러 단계에 걸쳐 **같은 대상을 이어서 보여줄 때는 크기와 채우기 방식이 같아야 한다**(MUST). 단계가 바뀌며 커지거나 작아지거나 잘리면, 사용자는 **다른 것으로 바뀌었다고 읽는다.**

이 값은 **한 곳에서 정해 공유해야 한다**(SHALL). 화면마다 따로 적어두고 주석으로 맞추게 해서는 안 된다(MUST NOT) — 한쪽만 고쳐지면 어긋난 것을 아무도 못 잡는다.

#### Scenario: 분석으로 넘어갈 때의 사진
- **WHEN** 회원이 사진을 고르고 분석하기를 눌러 대기 화면으로 넘어가면
- **THEN** 조금 전에 보던 사진이 같은 크기·같은 비율로 그대로 이어진다
