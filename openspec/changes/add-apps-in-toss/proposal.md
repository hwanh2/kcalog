## Why

kcalog의 유입 경로는 지금 웹 검색과 PWA 설치뿐이다. 설치 없이 열리는 토스 미니앱(앱인토스)에 같은 앱을 올리면 토스 사용자에게 바로 닿을 수 있다. 백엔드는 그대로 쓰고 프론트 빌드만 하나 더 만들면 되므로, 기존 웹을 유지한 채 입구를 하나 늘린다(2026-10-10 결정).

사업자 등록 전이라 토스 로그인은 쓸 수 없다. 비게임 미니앱이 쓸 수 있는 익명 사용자 키(`getAnonymousKey`)로 회원을 식별한다. kcalog는 이름이나 연락처가 필요 없고 "같은 사람인지"만 알면 되기 때문이다.

## What Changes

- 프론트에 토스 빌드 타깃을 추가한다. 같은 코드에서 웹 빌드(PWA, 카카오 로그인)와 토스 빌드(`.ait` 번들)를 따로 만든다.
- 두 빌드가 갈릴 필요가 없는 화면은 웹도 토스 기준에 맞춘다(2026-10-10 결정): 떠 있는 하단 탭바, "촬영"과 "앨범" 사진 버튼, 생성형 AI 고지. 그 밖의 웹 동작은 바뀌지 않는다.
- 토스 빌드는 랜딩, 로그인, 설치 안내 없이 앱 화면(`/app`)으로 바로 들어간다.
- 백엔드에 앱인토스 익명 키 로그인 엔드포인트를 추가한다. 프론트가 받은 1회용 인가 코드를 서버가 앱인토스 API(mTLS)로 익명 키와 교환하고, 그 키로 회원을 찾거나 만든 뒤 access 토큰을 준다.
- 회원 provider에 `TOSS`를 추가한다. 카카오 회원과 토스 회원은 별개 계정이다.
- 토스 빌드는 리프레시 쿠키를 쓰지 않는다. iOS WebView가 서드파티 쿠키를 막기 때문이다. access 토큰이 만료되면 익명 키 로그인을 조용히 다시 한다.
- 토스 빌드의 화면을 앱인토스 출시 기준에 맞춘다.
  - 앱 헤더를 없앤다. 로고와 앱 이름은 토스 내비바가 보여 주고, 프로필 진입은 내비바 기능 버튼으로 옮긴다.
  - 토스 내비바의 뒤로가기 이벤트로 화면을 되돌리고, 첫 화면에서는 미니앱을 닫는다. 자체 뒤로가기 버튼은 숨긴다.
  - 사진은 SDK 카메라와 앨범 API로 받는다.
  - 로그아웃 메뉴를 숨긴다.
- 백엔드 CORS 허용 목록에 토스 미니앱 origin을 더한다(환경 변수만 바뀐다).
- 개인정보 처리방침 페이지(`/privacy`)를 만들고 웹 랜딩, 로그인, 프로필에서 연결한다. 앱인토스 등록에 필요하고, 웹도 처리방침 없이 운영되고 있었다.
- 회원 탈퇴를 추가한다. 탈퇴하면 모든 기록과 사진을 지운다. 처리방침의 삭제 방법이 되고, 기존에 탈퇴 수단이 없었다.
- 테스트용 인증서 파일을 저장소에 두지 않는다. 테스트가 실행될 때 만든다.
- 토스 앱이 익명 키 기능을 모르는 옛 버전이면 업데이트를 안내한다.
- 온보딩을 마치면 목표에 따라 "익명의 다이어터1234" 같은 기본 닉네임을 붙이고, 프로필에서 바꿀 수 있게 한다. 토스 회원은 이름을 받지 않기 때문이다. 웹도 같다.
- AI PT 코치 대화에 안전장치를 붙인다. 앱인토스 AI 채팅 기준(위험 발화 필터링, 일관된 거절, 자해 관련 안전 응답)을 맞추기 위해서다. 같은 백엔드라 웹에도 함께 적용된다.

## Capabilities

### New Capabilities
- `privacy-policy`: 개인정보 처리방침 공개 페이지.
- `apps-in-toss`: 토스 미니앱 빌드 타깃. 진입 경로, 토스 내비바와 뒤로가기, 탭바, 사진 입력, 생성형 AI 고지, 웹 전용 기능 제외를 다룬다.

### Modified Capabilities
- `ai-coaching`: 코치 대화의 질문과 답을 안전 검사하고, 걸리면 고정 안전 응답을 준다.
- `member-profile`: 회원 탈퇴를 추가하고, 프로필 수정에 닉네임을 더한다. 토스 빌드에는 로그아웃이 없다.
- `onboarding`: 온보딩 완료 시 기본 닉네임을 붙인다.
- `auth`: 앱인토스 익명 키 로그인을 추가한다. 토스 빌드는 리프레시 쿠키 대신 재로그인으로 access 토큰을 갱신한다. `provider + provider_id` 식별 규칙에 TOSS가 들어간다.

## Impact

- 프론트
  - 의존성: `@apps-in-toss/web-framework` (SDK 3.x)
  - 신규: `apps-in-toss.config.ts`, 토스 빌드 모드 설정, 플랫폼 분기 모듈
  - 수정: `vite.config.ts`, `App.tsx`, `auth/AuthProvider.tsx`, `api/client.ts`, `shell/AppShell.tsx`, `features/meal/AiRecordPanel.tsx`, `features/onboarding/WizardShell.tsx`, `pages/ProfilePage.tsx`
- 백엔드
  - 신규: 앱인토스 API 클라이언트(mTLS), 익명 키 로그인 서비스와 엔드포인트
  - 수정: `Provider` enum, `AppProperties`, `application.yml`
  - `TOSS` provider는 마이그레이션 없음(provider 컬럼이 문자열). 탈퇴를 위해 `V24__member_delete_cascade.sql`로 외래 키 세 개에 CASCADE를 건다.
- 운영
  - 앱인토스 콘솔 등록, mTLS 인증서 발급, `CORS_ALLOWED_ORIGINS`에 `https://<appName>.apps.tossmini.com`과 `https://<appName>.private-apps.tossmini.com` 추가
  - 토스 번들 업로드는 이번 change에서 수동(`ait deploy`)으로 한다. CI 연동은 하지 않는다.
- 미확인 위험: 사업자 없이 mTLS 인증서를 발급받을 수 있는지 문서에 없다. 막히면 사업자 등록 후 진행한다.
