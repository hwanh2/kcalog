## ADDED Requirements

### Requirement: 토스 빌드 타깃
프론트엔드는 같은 소스에서 웹 빌드와 토스 빌드를 따로 만들 수 있어야 한다(SHALL). 토스 빌드는 앱인토스 SDK로 `.ait` 번들을 만들어야 한다(SHALL). 웹 빌드는 이 스펙이 두 빌드에 함께 적용한 항목(하단 탭바 형태, 사진 입력, 생성형 AI 고지) 외에는 토스 빌드 추가 전과 같게 동작해야 한다(MUST). 웹 번들에는 앱인토스 SDK 코드가 들어가지 않아야 한다(MUST NOT). 토스 전용 코드(SDK 호출)는 웹 빌드 실행 중에 호출되지 않아야 한다(MUST NOT).

#### Scenario: 웹 빌드는 그대로
- **WHEN** 웹 빌드를 만들면
- **THEN** PWA manifest와 service worker가 포함되고, 카카오 로그인과 랜딩 페이지가 지금처럼 동작한다

#### Scenario: 토스 빌드 산출물
- **WHEN** 토스 빌드를 만들면
- **THEN** `.ait` 번들이 생성되고, 번들에 PWA manifest와 service worker 등록 코드가 들어가지 않는다

### Requirement: 토스 빌드의 진입 경로
토스 빌드는 랜딩, 로그인, 설치 안내 화면 없이 앱 화면으로 진입해야 한다(SHALL). 진입 시 회원 식별을 마친 뒤 기존 온보딩 판정(`onboarding` 스펙)을 그대로 따라야 한다(SHALL). 진입하자마자 바텀시트를 띄우지 않아야 한다(MUST NOT).

#### Scenario: 첫 진입
- **WHEN** 처음 쓰는 토스 사용자가 미니앱을 열면
- **THEN** 로그인 화면 없이 회원이 만들어지고 온보딩 화면으로 이동한다

#### Scenario: 재진입
- **WHEN** 온보딩을 마친 토스 사용자가 미니앱을 다시 열면
- **THEN** 이전 기록이 그대로 있는 홈 화면이 열린다

#### Scenario: 웹 전용 경로 접근
- **WHEN** 토스 빌드에서 `/`, `/login`, `/auth/callback` 경로로 진입하면
- **THEN** 앱 화면(`/app`)으로 이동한다

### Requirement: 토스 내비바와 뒤로가기
토스 빌드는 토스 공통 내비바를 사용해야 한다(SHALL). 앱 헤더와 온보딩 머리에 자체 로고를 두지 않아야 한다(MUST NOT). 토스 내비바가 등록된 로고와 앱 이름을 보여 준다. 토스 내비바의 뒤로가기와 Android 백버튼은 열린 시트가 있으면 그것부터 닫고, 없으면 앱 안의 직전 화면으로 돌아가야 하며, 되돌아갈 화면이 없는 첫 화면에서는 미니앱을 닫아야 한다(SHALL). 토스 내비바의 뒤로가기와 자체 뒤로가기 버튼이 동시에 보이지 않아야 한다(MUST NOT).

#### Scenario: 하위 화면에서 뒤로가기
- **WHEN** 사용자가 홈에서 프로필로 이동한 뒤 토스 내비바의 뒤로가기를 누르면
- **THEN** 홈 화면으로 돌아간다

#### Scenario: 시트가 열린 상태에서 뒤로가기
- **WHEN** 음식기록 화면에서 분석 결과 시트가 열린 채 뒤로가기를 누르면
- **THEN** 시트만 닫히고 음식기록 화면에 머문다

#### Scenario: 첫 화면에서 뒤로가기
- **WHEN** 미니앱 진입 직후 첫 화면에서 뒤로가기를 누르면
- **THEN** 미니앱이 닫힌다

#### Scenario: 온보딩 단계 되돌리기
- **WHEN** 온보딩 두 번째 단계에서 토스 내비바의 뒤로가기를 누르면
- **THEN** 첫 번째 단계로 돌아가고, 화면 안의 자체 뒤로가기 버튼은 보이지 않는다

#### Scenario: 앱 헤더와 프로필 진입
- **WHEN** 토스 빌드에서 앱 화면을 열면
- **THEN** 앱 자체 헤더가 없고, 토스 내비바의 프로필 버튼을 누르면 프로필 화면으로 간다

### Requirement: 하단 탭바 형태
하단 탭은 웹과 토스 빌드 모두 화면 양옆과 아래에서 띄운 알약 형태여야 한다(SHALL). 앱인토스 UX 가이드가 탭바를 플로팅 형태로만 허용하며, 웹도 같은 모양으로 통일한다. 탭 구성(홈, 음식기록, 체중, 리포트, AI PT)과 각 탭의 목적지는 두 빌드가 같아야 한다(MUST).

#### Scenario: 탭 이동
- **WHEN** 토스 빌드에서 체중 탭을 누르면
- **THEN** 웹 빌드와 같은 체중 화면으로 이동한다

#### Scenario: 웹의 탭바 모양
- **WHEN** 웹에서 앱 화면을 열면
- **THEN** 하단 탭이 화면 끝에 붙지 않고 떠 있는 알약으로 보인다

### Requirement: 사진 입력
음식 사진 입력은 웹과 토스 빌드 모두 "촬영"과 "앨범" 두 버튼을 제공해야 한다(SHALL). 촬영은 카메라를 바로 열고, 앨범은 사진첩에서 고르게 한다. 웹은 브라우저 파일 입력을, 토스 빌드는 앱인토스 SDK의 카메라와 앨범 API를 써야 한다(MUST). 토스 빌드는 카메라와 앨범 권한을 번들 설정에 선언해야 한다(MUST). 권한을 거부해도 사진 외의 기록 방법(설명 입력, 직접 입력, 검색, 즐겨찾기)은 계속 쓸 수 있어야 한다(SHALL). 받은 사진은 두 빌드가 같은 분석 요청으로 전송해야 한다(SHALL).

#### Scenario: 카메라로 기록
- **WHEN** 사용자가 촬영 버튼을 누르고 사진을 찍으면
- **THEN** 그 사진으로 같은 음식 분석이 시작된다

#### Scenario: 앨범에서 고르기
- **WHEN** 사용자가 앨범 버튼을 누르면
- **THEN** 카메라가 아니라 사진첩이 열린다

#### Scenario: 권한 거부 (토스 빌드)
- **WHEN** 토스 빌드에서 사용자가 카메라 권한을 거부하면
- **THEN** 권한이 필요하다는 안내와 다시 요청하는 경로가 보이고, 설명 입력과 직접 입력은 정상 동작한다

### Requirement: 생성형 AI 고지
웹과 토스 빌드 모두 생성형 AI를 쓰는 기능(사진 분석, AI PT)에 AI가 결과를 만든다는 사실을 알려야 한다(SHALL). 고지는 기능 화면에 늘 보이게 둔다. AI가 만든 결과물에는 AI 생성물임을 배지로 표시해야 한다(SHALL): 사진 분석 결과는 "AI 추정", 코치 답변과 브리핑, 홈의 AI 코칭 카드는 "AI 생성".

#### Scenario: 사진 분석 화면
- **WHEN** 사용자가 사진 분석 화면을 열면
- **THEN** 분석 결과를 AI가 추정한다는 고지가 보인다

#### Scenario: 분석 결과 표시
- **WHEN** 사진 분석 결과가 화면에 나오면
- **THEN** 결과 제목 옆에 "AI 추정" 표시가 있다

#### Scenario: 코치 답변 표시
- **WHEN** AI PT에서 코치의 답이 화면에 나오면
- **THEN** 답 말풍선마다 "AI 생성" 표시가 있고, 내 질문에는 없다

### Requirement: 앱인토스 UX 라이팅
앱 화면의 문구는 웹과 토스 빌드 모두 해요체여야 한다(MUST). AI 코치의 답도 해요체로 말하도록 지시해야 한다(SHALL). 확인 다이얼로그의 왼쪽(기본) 버튼은 "닫기"여야 하며 "취소"를 쓰지 않는다(MUST NOT). 브라우저 기본 확인창(`window.confirm`)을 쓰지 않고 앱의 확인 시트를 써야 한다(MUST). 토스 빌드에서 메일 같은 외부 주소는 앱인토스 SDK의 openURL로 열어야 한다(SHALL). 웹 전용 화면(랜딩, 설치 안내)은 토스 빌드에 나오지 않아 이 요구에서 뺀다.

#### Scenario: 입력 오류 문구
- **WHEN** 사용자가 범위를 벗어난 키를 입력하면
- **THEN** "키는 100~230cm 사이로 입력해주세요"처럼 해요체로 안내한다

#### Scenario: 삭제 확인
- **WHEN** 사용자가 식사 기록을 지우려 하면
- **THEN** 확인 시트의 왼쪽 버튼은 "닫기"이고, 누르면 아무것도 지우지 않는다

#### Scenario: 수정 중 재분석
- **WHEN** 분석 결과를 고친 뒤 재분석을 요청하면
- **THEN** 브라우저 기본 창이 아니라 앱의 확인 시트로 수정한 값이 사라진다고 알린다

#### Scenario: 토스 빌드의 메일 링크
- **WHEN** 토스 빌드에서 처리방침의 연락처 메일을 누르면
- **THEN** SDK의 openURL로 메일 주소를 연다

### Requirement: 토스 빌드에서 빠지는 기능
토스 빌드는 다음을 노출하지 않아야 한다(MUST NOT): 앱 설치 안내, 웹 랜딩, 로그아웃 메뉴, 자사 웹이나 자사 앱으로 이동시키는 링크. 화면 핀치 줌은 막혀 있어야 한다(SHALL).

#### Scenario: 프로필 메뉴
- **WHEN** 토스 빌드에서 프로필 화면을 열면
- **THEN** 로그아웃 메뉴가 없다

#### Scenario: 외부 이동
- **WHEN** 토스 빌드의 어느 화면에서든
- **THEN** kcalog.site나 다른 자사 도메인으로 이동하는 링크가 없다
