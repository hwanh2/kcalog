## ADDED Requirements

### Requirement: 회원 탈퇴
시스템은 로그인한 회원이 `DELETE /api/members/me`로 탈퇴할 수 있게 해야 한다(SHALL). 탈퇴하면 회원과 그 회원의 모든 기록(식사, 체중, 분석 작업, 보정값, 즐겨찾기, 코치 대화와 브리핑, 칭찬, 의견, refresh 토큰)을 지우고, 스토리지에 저장된 그 회원의 사진(확정 식사 사진과 미확정 분석 사진)도 지워야 한다(MUST). 사진 삭제가 실패해도 탈퇴는 성공으로 끝나며 실패를 로그에 남긴다(SHALL). 응답은 웹의 refresh 쿠키를 만료시켜야 한다(SHALL). 프론트엔드는 되돌릴 수 없다는 확인을 받은 뒤에만 탈퇴를 요청해야 하며(MUST), 탈퇴 후 웹은 랜딩으로, 토스 빌드는 미니앱을 닫아야 한다(SHALL).

#### Scenario: 탈퇴
- **WHEN** 식사, 사진, 체중, 즐겨찾기, 보정값이 있는 회원이 탈퇴를 요청하면
- **THEN** 204와 만료된 refresh 쿠키를 돌려주고, 회원과 모든 기록이 지워지며, 저장된 사진도 지워진다

#### Scenario: 인증 없는 탈퇴 요청
- **WHEN** access 토큰 없이 탈퇴를 요청하면
- **THEN** 401을 반환하고 아무것도 지우지 않는다

#### Scenario: 확인 없이 탈퇴하지 않음
- **WHEN** 사용자가 프로필의 회원 탈퇴를 누르면
- **THEN** 모든 기록이 지워지고 되돌릴 수 없다는 확인 시트가 먼저 뜨고, 확인해야 요청을 보낸다

#### Scenario: 토스 빌드의 탈퇴 후
- **WHEN** 토스 빌드에서 탈퇴가 끝나면
- **THEN** 미니앱이 닫힌다. 다시 열면 빈 새 회원으로 시작한다

## MODIFIED Requirements

### Requirement: 로그아웃 진입점
웹 빌드의 프로필 화면은 로그아웃 기능을 제공해야 한다(SHALL). 토스 빌드는 로그아웃을 제공하지 않는다(MUST NOT). 익명 키로 들어와서 로그아웃해도 다음 요청에서 같은 회원으로 다시 들어오기 때문이다.

#### Scenario: 프로필에서 로그아웃
- **WHEN** 웹에서 회원이 프로필 화면의 로그아웃을 누르면
- **THEN** auth의 로그아웃 처리가 수행되고 로그인 화면으로 이동한다

#### Scenario: 토스 빌드의 프로필
- **WHEN** 토스 빌드에서 프로필 화면을 열면
- **THEN** 로그아웃 버튼이 없다

### Requirement: 목표·프로필 수정
시스템은 닉네임, 키, 목표 체중, 활동량, 일일 칼로리 목표를 수정할 수 있어야 한다(SHALL). 키·목표 체중·활동량이 변경되면 새 제안 칼로리를 계산해 보여주되, 최종 저장값은 사용자가 확정한 값이어야 한다(MUST). 닉네임은 앞뒤 공백을 지워 저장하며, 비었거나 20자를 넘으면 저장하지 않아야 한다(MUST NOT). 웹과 토스 빌드에서 같다.

#### Scenario: 활동량 변경 후 재계산 제안
- **WHEN** 회원이 활동량을 LOW에서 HIGH로 변경하면
- **THEN** 새 제안 일일 칼로리가 표시되고, 회원이 확정한 값이 저장된다

#### Scenario: 칼로리 목표 직접 수정
- **WHEN** 회원이 일일 칼로리 목표만 직접 수정해 저장하면
- **THEN** 재계산 없이 입력한 값이 저장된다 (온보딩과 동일한 유효 범위 검증 적용)

#### Scenario: 닉네임 수정
- **WHEN** 회원이 프로필 편집에서 닉네임을 "  새벽러너 "로 바꿔 저장하면
- **THEN** "새벽러너"로 저장되고 홈 인사말과 프로필 카드에 반영된다

#### Scenario: 빈 닉네임
- **WHEN** 회원이 닉네임을 비우고 저장하면
- **THEN** 오류가 표시되고 기존 닉네임이 유지된다
