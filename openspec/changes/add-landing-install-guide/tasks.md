## 3. 설치 상태 판정

- [x] 3.1 `useInstallState()` 훅 — `installed` / `in-app` / `desktop` / `installable` / `ios` / `android`를 이 우선순위로 판정한다
  - `display-mode: standalone` + iOS `navigator.standalone`
  - 데스크톱이 `installable`보다 앞선다 — 데스크톱 크롬도 프롬프트를 쏘지만 사진으로 기록하는 앱이라 설치가 무의미하다
  - 프롬프트는 한 번 쓰면 재사용할 수 없다 — 거절 시 `ios`/`android` 수동 안내로 내려가야 버튼이 죽지 않는다
- [x] 3.3 **인앱 브라우저 감지** — 카카오톡·인스타그램·페이스북·네이버·라인 웹뷰. 여기서는 홈 화면 추가가 막히므로 다른 안내를 해야 한다
  - 링크를 뿌릴 가장 유력한 경로가 카카오톡이다. 감지하지 못하면 카톡으로 받은 사람은 안내대로 따라 해도 설치에 실패한다
  - iPadOS 13+는 UA가 `Macintosh`로 나오므로 `navigator.maxTouchPoints > 1`로 구분
  - `beforeinstallprompt`를 잡아 보관하고, 설치 실행 함수를 함께 내보낸다
- [x] 3.2 훅 테스트 — 상태 판정, 설치 완료 시 안내 비노출, 태블릿이 모바일로 분류되는지, 거절 후 수동 안내로 내려가는지
  - 판정이 흩어지면 한쪽에서 standalone 검사가 빠지는 사고가 난다(참고 구현에서 실제로 발생). 테스트로 단일 지점을 고정한다
