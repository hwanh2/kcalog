# 설계 — 앱 화면 모션

전제: DESIGN.md 모션 규칙(`transform`/`opacity`만, `transition: all` 금지, reduced-motion에서 정지)을 그대로 따른다. 라이브러리는 들이지 않는다 — 이 레포는 아이콘까지 인라인 SVG로 두는 기조다.

## D1. reduced-motion은 이미 전역으로 걷혀 있다

`index.css`에 `*`를 훑어 `animation-duration`·`transition-duration`을 0.01ms로 만드는 블록이 이미 있다. **새로 넣는 CSS 연출은 별도 조치 없이 함께 멈춘다.**

⚠️ 이 블록은 **CSS만** 잡는다. JS로 값을 굴리는 연출(숫자 카운트업 등)은 `canAnimate()`를 직접 봐야 한다. 이번 여섯 자리는 전부 CSS라 해당 없다 — 그래서 `canAnimate()`를 `features/landing/`에서 꺼내오지 않았다. 쓰지도 않을 것을 미리 옮기면 랜딩 전용이라는 사실만 흐려진다.

## D2. 진행 바 — 미는 방식

채움을 트랙 폭 전체로 두고 **왼쪽으로 밀어 넣는다**(`translateX(pct - 100%)`).

| 방식 | 문제 |
| --- | --- |
| `width` 전환 | 레이아웃을 다시 계산한다(DESIGN.md 위반). 예전 `WeightProgressCard`가 이랬다 |
| `scaleX` | `rounded-full` 끝을 함께 눌러 **30%쯤에서 알약 끝이 뾰족해진다** |
| **밀기** | 채움이 늘 제 크기라 끝 모양이 그대로고, 넘친 부분은 트랙이 잘라낸다 |

`ui/ProgressBar`로 묶어 홈 매크로 바와 프로필 체중 바가 같은 부품을 쓴다. 둘로 나뉜 채 두면 한쪽만 고쳐지고 규칙이 갈라진다 — 실제로 갈라져 있었다.

**자라나게 하려면 두 번 그려야 한다.** 마운트할 때 최종값으로 그리면 전환이 걸릴 구간이 없다. `useState(0)` → `useEffect`로 값을 넣어, 첫 페인트는 빈 바, 다음 프레임에 값으로 간다.

## D3. 칼로리 링 — dasharray가 아니라 dashoffset

예전에는 `strokeDasharray={`${pct}, 100`}`로 채움 길이 자체를 바꿨다. 값이 바뀌면 호가 **순간이동한다.**

둘레가 100이 되게 그린 path이므로 `strokeDasharray="100"`(원 하나를 덮는 dash)로 고정하고 **`strokeDashoffset`으로 얼마나 밀어둘지**만 바꾼다. offset은 전환이 걸려 링이 그려지듯 채워진다.

`stroke-dashoffset`은 `transform`/`opacity`가 아니지만 **레이아웃을 유발하지 않는** 페인트 속성이고, 원호 채움을 그 둘로 표현할 방법이 없다. 스펙의 예외 조항이 이것을 가리킨다.

**홈에 들어올 때마다 다시 돈다.** 한 번만 돌게 하려면 모듈 밖에 "본 적 있음"을 들고 있어야 하는데, 그러면 StrictMode의 이중 마운트에서 **개발 중에만 연출이 사라진다**(첫 마운트가 깃발을 세우고 두 번째가 건너뛴다). 숨은 상태를 만들면서 개발 환경만 다르게 도는 쪽이, 홈에 들어올 때 700ms 링이 도는 쪽보다 나쁘다.

## D4. 밑줄 탭 — 자리를 재지 않는다

탭이 전부 `flex-1`이라 폭이 같다. 그래서 DOM을 재지 않고 **비율만으로** 옮길 수 있다.

```
껍데기  width: 100/n %      transform: translateX(index × 100%)
안쪽    mx-2 flex-1         ← 좌우 여백은 여기서 (예전 inset-x-2와 같은 값)
```

껍데기와 안쪽을 나눈 이유: 여백을 껍데기에 주면 폭 계산(`100/n%`)에 섞여 칸이 어긋난다.

`activeIndex < 0`이면 밑줄을 그리지 않는다 — 목록에 없는 값이 선택으로 들어오면 0번 자리에 밑줄이 남는다.

## D5. 방금 담긴 줄 — 직전 목록에 없던 id

어느 줄이 새 줄인지는 서버가 알려주지 않으므로 **직전 목록과 비교**한다.

```ts
const seenRef = useRef<{ date: string; ids: Set<number> } | null>(null)
```

날짜를 함께 들고 있는 게 핵심이다. id만 들고 있으면 **날짜를 옮길 때 그 날 목록 전체가 "새 것"이 되어** 한꺼번에 움직이고, 정작 방금 담은 줄이 묻힌다. 첫 목록도 같은 이유로 통째로 기존 취급한다.

날짜를 ref에 함께 넣으면 초기화 이펙트를 따로 두지 않아도 된다 — 이펙트 두 개의 실행 순서에 기대는 코드가 사라진다.

⚠️ 이 테스트는 **한 번 헛통과했다.** 날짜를 옮긴 뒤 `findAllByText(/삶은달걀/)`로 기다렸는데 그 이름이 아래 음식 목록에도 있어, 새 기록이 그려지기 전에 단언이 돌았다. 가드를 빼도 통과했다. 기록 줄에만 있는 문구로 바꾸고, **가드를 다시 빼서 실제로 실패하는 것까지 확인**했다.

## D6. 시트는 열 때만 연출한다

닫히는 연출은 넣지 않았다. 언마운트를 늦춰야 하고(닫힘 상태를 따로 들고 있어야 한다) 그동안 딤이 클릭을 먹는 구간이 생긴다. **얻는 것에 비해 상태가 는다.**

시트는 열릴 때 마운트되므로 CSS 키프레임이 저절로 한 번만 돈다 — 상태가 필요 없다.

## D7. 버튼은 공용 부품에서

`ui/form`의 `Button`에 `active:scale-[0.98]`을 넣으면 그것을 쓰는 모든 자리가 함께 얻는다(`RecordButton`의 "기록하기"도 여기 포함된다). 공용 부품을 쓰지 않는 자리 중에서는 **가장 자주 눌리는 체중 저장 버튼**만 같이 손봤다 — 나머지는 이번 요청 밖이다.
