# daily-dashboard (delta)

## MODIFIED Requirements

### Requirement: 목표 대비 잔여와 구성 비율
시스템은 회원의 일일 칼로리 목표 대비 잔여 칼로리와, 탄단지 구성 비율을 산출할 수 있는 탄단지 gram 합계를 제공해야 한다(SHALL). 목표를 초과하면 잔여는 음수로 표현해야 한다(MUST). 구성 비율(%) 자체는 gram 합계로부터 클라이언트가 파생한다 — 서버는 gram 합계만 authoritative로 반환한다(design D6). 시스템은 일일 칼로리 목표에서 파생한 **탄단지 목표(g)** 를 함께 반환해야 한다(SHALL) — 탄 50%/단 30%/지 20% kcal 비율 기준 g 환산(탄·단 4kcal/g, 지 9kcal/g), 칼로리 목표가 없으면 null(design D3).

#### Scenario: 잔여 칼로리
- **WHEN** 대시보드를 조회하면
- **THEN** `daily_kcal_target − 총 섭취`를 잔여 칼로리로, 탄단지 gram 합계와 함께 반환한다

#### Scenario: 목표 초과
- **WHEN** 총 섭취가 목표를 초과하면
- **THEN** 잔여 칼로리를 음수로 반환한다

#### Scenario: 탄단지 목표 반환
- **WHEN** 칼로리 목표가 설정된 회원이 대시보드를 조회하면
- **THEN** 탄단지 각각의 목표 g가 50/30/20 비율로 환산되어 반환된다

#### Scenario: 목표 미설정 회원
- **WHEN** 칼로리 목표가 없는 회원이 대시보드를 조회하면
- **THEN** 탄단지 목표는 null로 반환된다

## ADDED Requirements

### Requirement: 홈 화면 구성
홈 화면은 디자인 템플릿(`docs/png/01-home.png`) 기준으로 다음 요소를 표시해야 한다(SHALL): 날짜·인사 헤더, 남은 칼로리 링 게이지(섭취/목표 병기, 목표 초과 시 초과 표시), 탄단지 목표 대비 진행 바(섭취 g/목표 g), 체중 추세 미니카드(최근 체중·7일 변화·목표까지 남은 kg·스파크라인), 끼니 목록(끼니 구분·시각·음식명·탄단지·칼로리), 다음 끼니 촬영 유도 카드. 끼니 목록에서 기존과 동일하게 개별 기록의 수정·삭제가 가능해야 한다(MUST).

#### Scenario: 홈 표시
- **WHEN** 온보딩을 마친 회원이 홈에 진입하면
- **THEN** 링 게이지·매크로 진행 바·체중 미니카드·끼니 목록·촬영 유도 카드가 표시된다

#### Scenario: 목표 초과 표시
- **WHEN** 섭취가 목표를 초과하면
- **THEN** 링 게이지와 잔여 표기가 초과 상태(위험 색·초과량)로 표시된다

#### Scenario: 체중 기록 없음
- **WHEN** 최근 체중 기록이 없으면
- **THEN** 체중 미니카드는 기록 유도 안내를 표시한다

#### Scenario: 끼니 수정·삭제
- **WHEN** 회원이 끼니 목록의 항목에서 수정 또는 삭제를 수행하면
- **THEN** 기존 식사 수정·삭제 규칙(meal-logging)대로 동작하고 홈 집계가 갱신된다

### Requirement: 날짜 이동
홈은 조회 날짜를 이동할 수 있어야 하며(SHALL), 이동한 날짜의 집계·끼니 목록을 동일한 구성으로 표시해야 한다(MUST). 기본값은 오늘(KST)이어야 한다(MUST).

#### Scenario: 이전 날짜 조회
- **WHEN** 회원이 홈에서 날짜를 이전으로 이동하면
- **THEN** 해당 날짜의 집계와 끼니 목록이 표시되고 수정·삭제도 가능하다
