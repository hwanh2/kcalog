# Design: redesign-app-shell

## Context

2026-08-10 재계획으로 최종 IA(5탭 + 카메라 FAB)와 화면 템플릿(`docs/png/`)이 확정됐다. 현재 구현은 3탭(오늘/기록/프로필) 셸 위에 대시보드·기록·체중 위젯이 얹혀 있다. 이 change는 구조(셸)와 첫 화면(홈)을 최종 형태로 바꾸되, 데이터 모델·API 파이프라인은 건드리지 않는다(비동기 분석·사진 저장은 후속 change).

## Decisions

### D0. 디자인 시안 v2 채택 (2026-08-10)
최초 png 템플릿(크림 배경·중앙 FAB·기록 탭 폐지) 대신 사용자가 제공한 **v2 시안**을 기준으로 확정. 원본 HTML 목업이 `docs/design-mockup-v2.html`(로컬 전용)로 보관되어 있으며 5개 화면(홈·음식기록 분석 상태·체중·리포트·AI PT)과 온보딩 모달·항목 편집 바텀시트까지 포함 — **이후 모든 화면 change는 이 목업이 1차 기준**이고, 캡처본은 `docs/png/01-home-v2-*.png`. 핵심 차이: slate 배경·비비드 오렌지·매크로 3색(앰버/로즈/시안), **음식기록 탭 유지**, **카메라 FAB 우하단 플로팅**(촬영 화면에선 숨김), **글로벌 앱 헤더**(로고·프로필 버튼).

### D1. 탭 구성과 기존 화면의 행선지 (v2)
- 5탭: **홈 / 음식기록 / 체중 / 리포트 / AI PT** + **우하단 플로팅 카메라 FAB** — v2 시안 하단 바와 동일.
- **음식기록 탭 유지**: 기존 `RecordsPage`(날짜별 조회·수정·삭제)가 그대로 음식기록 탭이 된다. v1의 "기록 탭 폐지→홈 흡수" 결정은 철회. 홈의 "오늘 기록한 식사" 목록은 조회 중심이며 "전체보기"로 음식기록 탭에 진입한다.
- **글로벌 앱 헤더**: 셸 상단에 로고·앱명(임시 kcalog)·프로필 버튼을 고정 배치(모든 탭 공통) — v2 목업의 App Header Bar와 동일. 프로필 진입은 이 헤더 버튼(`/profile` 라우트 유지). 스트릭(🔥 N일) 배지는 `add-ai-coaching`에서.
- **체중 탭**: 기존 `WeightPanel` + `WeightTrend` 이식만. 고도화(가중이동평균·목표 예상)는 `enhance-weight-tab`에서.
- **리포트·AI PT 탭**: "준비 중" placeholder. 탭 자체를 숨기지 않는 이유 — 최종 IA를 처음부터 고정해 이후 change가 셸을 다시 만지지 않게 함.
- 카메라 FAB → 기존 `MealRecordPage`(촬영→분석→저장) 진입. 저장 후 홈으로 복귀.

### D2. 디자인 토큰 — Tailwind v4 `@theme` 교체 (v2 목업 정식 팔레트)
목업 HTML의 tailwind.config 정의를 그대로 사용: primary `#FF6B00`(600 `#E55A00`, 50 `#FFF5ED`), 매크로 탄=앰버 `#F59E0B`(bg `#FEF3C7`)·단=로즈 `#EF4444`(bg `#FEE2E2`)·지=시안 `#06B6D4`(bg `#CFFAFE`), slate 계열 캔버스 `#F8FAFC`·잉크 `#0F172A`·뮤티드 `#94A3B8`·보더 `#E2E8F0`, 성공 에메랄드 `#059669`(soft `#ECFDF5`). 카드 라운드 1.5rem(rounded-3xl). 기존 화면(온보딩·프로필·촬영 흐름)은 토큰 교체의 영향만 받고 레이아웃 변경 없음.

### D3. 탄단지 목표 — 서버 파생 계산, 저장 없음
- 목표 매크로(g)는 `dailyKcalTarget`에서 비율로 파생: **탄 50% / 단 30% / 지 20%** (kcal 기준, 탄·단 4kcal/g, 지 9kcal/g → g 환산 후 반올림). 감량 목적의 일반적 권장 범위이며, 적응형 TDEE change(`add-adaptive-tdee`)에서 개인화로 대체될 기준값.
- Member 스키마에 저장하지 않고 `DashboardService`에서 계산해 `DashboardResponse`에 `carbTargetG/proteinTargetG/fatTargetG`(Integer, target 없으면 null)로 내려준다. 이유: 아직 사용자가 조정할 수 없는 파생값이라 저장하면 TDEE 도입 때 마이그레이션 부채가 됨.

### D4. 홈 화면 데이터 소스 — 기존 API 재사용
- 링 게이지·매크로 달성도: `GET /api/dashboard?date=`. 홈 "오늘 기록한 식사" 목록은 음식명 표시를 위해 `GET /api/meals?date=` 기준(조회 전용, 수정·삭제는 음식기록 탭).
- 체중 미니카드: 기존 `GET /api/weights?from=&to=`(30일) 재사용 — 최근 체중, 7일 전 대비 변화, 스파크라인.
- 신규 API 없음. 백엔드 변경은 D3의 응답 필드 추가뿐.
- v2 시안의 "활동 소비량 / 순 섭취량" 행은 데이터 소스(운동 기록)가 없어 이번 change에서는 표시하지 않는다 — workout 기능 도입 시 추가(백로그).
- v2 시안의 AI 코칭 카드·스트릭(🔥 N일) 배지는 `add-ai-coaching`에서 구현 — 이번엔 자리 미구현.

### D5. 촬영 유도 카드
당일 기록된 끼니 구분(아침/점심/저녁)을 보고 다음 끼니를 제안하는 단순 규칙(시각 기반 기본값 재사용). 미기록 시 "아침을 촬영해 기록해요" 형태. 로직은 프론트 순수 함수로 두고 단위 테스트.

### D6. 링 게이지·스파크라인 — 인라인 SVG 유지
기존 `WeightTrend`와 동일하게 차트 라이브러리 없이 인라인 SVG(원호 `stroke-dasharray` 링, polyline 스파크라인). 의존성 최소화 방침 유지.

## Risks / Trade-offs

- [기록 탭 폐지로 과거 날짜 편집 동선이 홈 날짜 이동에 묶임] → 템플릿 IA와 일치하고, 리포트 탭이 생기면 과거 조회는 리포트에서 보완 가능. 1차 수용.
- [매크로 비율 50/30/20 고정] → 사용자 조정 불가는 한계지만 TDEE change에서 개인화 예정. design 문서에 기준 명시로 추적 가능.
- [placeholder 탭 2개 노출] → "준비 중" 화면이 미완성 인상을 줄 수 있으나, 셸 재작업 방지 이득이 더 큼.
- [홈이 dashboard+meals+weights 3개 쿼리 사용] → TanStack Query 캐시로 중복 호출 없음. 통합 API는 트래픽 문제가 생길 때 고려.

## Migration Plan

- DB 마이그레이션 없음. 백엔드는 응답 필드 추가(additive)라 프론트 구버전과도 호환.
- 프론트는 라우트 재배치(`/records` 제거, `/weight`·`/report`·`/ai-pt` 추가). PWA 정적 배포라 단순 교체.
