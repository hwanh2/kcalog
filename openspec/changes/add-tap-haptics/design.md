# 설계 — 하단 탭 누름 응답

## D1. 진동 하나에 기대지 않는다

조사 결과 **아이폰에서는 진동이 거의 안 된다.**

```
iOS 사파리 Vibration API   3.2 ~ 26.5 전 버전 미지원 (caniuse)
switch 편법                iOS 17.4 ~ 26.4 에서만, 26.5에서 Apple이 막음
```

진동만 넣으면 아이폰 사용자에게는 **아무것도 바뀌지 않는다.** 그래서 어느 기기에서나 오는 응답은 눌림(`.press`)이 맡고, 진동은 **되면 좋은 것**으로 얹는다.

`.press`는 이미 저장·기록하기 버튼이 쓰고 있다. 하단 탭에만 빠져 있었다.

## D2. 지원 확인은 호출부의 일이 아니다

```ts
tapHaptic()   // 부르는 쪽은 확인할 것이 없다
```

`if (navigator.vibrate) ...`를 자리마다 적으면 다음에 추가하는 자리에서 빠뜨린다. 안 되는 환경에서는 조용히 넘어가도록 함수 하나가 전부 삼킨다.

표준이 먹으면 거기서 끝낸다 — `navigator.vibrate()`가 참을 돌려주면 편법은 타지 않는다. 안드로이드에서 스위치를 만들 이유가 없다.

## D3. 편법의 모양 — 만들었다 지우지 않고 하나를 둔다

iOS 편법은 **`<label>`을 클릭해야** 울린다. 스위치를 직접 `click()`하면 상태만 바뀌고 Taptic Engine은 돌지 않는다.

부를 때마다 만들었다 지우는 구현이 흔한데, 그러면 화면 낭독기가 **갑자기 나타난 컨트롤을 읽을 틈**이 생긴다. 한 번 만들어 두고 상태만 바꾼다.

숨기는 방법:

| | 이유 |
| --- | --- |
| `position: fixed`, 1×1, `opacity: 0` | 레이아웃에 끼지 않는다 |
| `display: none`은 안 쓴다 | 클릭이 통하지 않는다 |
| `pointer-events: none` | 실수로 손가락에 닿지 않는다 |
| `aria-hidden="true"` (label·input 둘 다) | 화면 낭독기가 읽지 않는다 |
| `tabIndex = -1` | 키보드 이동이 빈 칸을 지나가지 않는다 |

`switch` 속성은 JSX가 아니라 `setAttribute`로 붙인다 — React가 모르는 속성을 거치지 않게 한다.

## D4. 조용히 안 되는 것이 이 편법의 진짜 비용

막힌 기기에서도 **오류는 나지 않는다.** 그래서 나중에 "왜 진동이 없지?"의 원인을 찾기 어렵다.

되돌리기 쉬운 형태로 둔다 — 편법은 `lib/haptics.ts` 한 파일 안에 있고, 지우면 `navigator.vibrate` 한 줄만 남는다. Apple이 남은 통로마저 닫으면 그 파일에서 함수 하나를 지우면 된다.

## D5. 하단 탭에만 붙인다

요청이 "하단의 버튼"이었다. FAB과 화면 안 버튼들은 붙이지 않았다 — **누르는 것마다 울리면 진동이 신호가 아니라 소음이 된다.** 탭 이동은 화면이 통째로 바뀌는 큰 전환이라 답할 값어치가 있다.
