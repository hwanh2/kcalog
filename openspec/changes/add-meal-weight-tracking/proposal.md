## Why

인증·온보딩(add-auth-onboarding)으로 회원이 목표를 설정하는 데까지 왔지만, 아직 **매일 쓸 이유**가 없다. 제품의 핵심 루프인 "사진 한 장으로 10초 안에 식사 기록 → 하루 요약 확인"과 "체중 추이 확인"이 비어 있다. 이 change가 그 핵심 루프를 채워 실사용 가능한 MVP를 완성한다.

범위는 2026-07-28 개정(1차 축소)과 2026-08-05 개정(GPT-5.4 mini)을 따른다.

## What Changes

- **식사 기록**: 사진 촬영/선택 → 백엔드 분석 API(GPT-5.4 mini)로 총 칼로리·탄·단·지 추정 → 사용자 확인·수정 → 저장. 분석 결과는 확인 후에만 DB 저장, 사진은 저장하지 않는다(분석 입력으로만 사용 후 폐기). 사진 없이 숫자만 수동 기록도 지원.
- **식사 조회·수정·삭제**: 날짜별 기록 조회, 저장된 기록 수정·삭제.
- **체중 기록**: 하루 1회 입력(같은 날 재입력 시 upsert), 기간별 추이 조회. (weight_log 테이블은 온보딩에서 이미 생성됨 — 이 change는 입력·조회 기능을 추가)
- **하루 대시보드(최소)**: 오늘 섭취 총계, 목표 대비 잔여 칼로리, 탄단지 비율, 식사 타임라인.
- **디자인·앱 셸**: 스타일 시스템 도입과 3탭(오늘/기록/프로필) 레이아웃. 기존 온보딩·프로필 화면도 이 셸·스타일에 편입.
- **AI 평가(eval)**: 한식 사진 + 기대값 평가 세트와 채점 스크립트로 GPT-5.4 mini 정확도 측정, 승격/강등·프롬프트 개선 판단 근거 확보.
- 일일 분석 호출 횟수 제한(비용 가드레일).

명시적 비범위(이후 change): 운동 기록, 주간 AI 리포트, 음식별 아이템 분석(meal_item), 사진 영구 보관.

## Capabilities

### New Capabilities
- `meal-logging`: 사진 AI 분석(확인 전 미저장)·확인/수정·저장, 수동 입력, 날짜별 조회·수정·삭제, 일일 분석 횟수 제한
- `weight-tracking`: 체중 하루 1회 입력(upsert), 기간별 추이 조회
- `daily-dashboard`: 오늘 섭취 총계·목표 대비 잔여·탄단지 비율·식사 타임라인
- `app-shell`: 스타일 시스템 + 3탭 네비게이션 레이아웃, 기존 화면 편입
- `meal-analysis-eval`: 한식 평가 세트 + 채점 스크립트로 분석 모델 정확도 측정

### Modified Capabilities
- (없음 — 기존 auth/onboarding/member-profile 스펙의 요구사항은 변경되지 않는다. 프로필·홈 화면의 시각적 편입은 구현 세부이며 스펙 요구사항 변경이 아님)

## Impact

- **백엔드**: `com.kcalog.domain.meal`(entity/controller/service/dto), `weight` 도메인에 입력·조회 API 추가, `report` 미도입. Flyway `V4__meal.sql`(meal 테이블 — 사진 단위 총량, meal_type, source). 외부 연동: OpenAI API(WebClient), 구조화 출력(JSON schema). 신규 설정: OpenAI API 키·모델명(설정값), 일일 분석 제한.
- **프론트**: 3탭 셸·라우팅 확장, 스타일 시스템(도구 선정 필요), 카메라/갤러리 입력·이미지 리사이즈, 식사 확인·수정 UI, 체중 입력·추이 그래프, 오늘 대시보드. 기존 온보딩·프로필 화면 편입.
- **eval**: `eval/` 디렉터리에 한식 사진·기대값·채점 스크립트.
- **환경변수**: `OPENAI_API_KEY`, 모델명, 일일 분석 제한. `.env.example` 갱신.
- **비용**: 분석 호출당 과금(약 $0.0018/장). 일일 제한으로 상한.
