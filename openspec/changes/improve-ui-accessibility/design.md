# Design: improve-ui-accessibility

## Context

`revamp-food-record-tab`으로 들어온 새 UI를 Vercel Web Interface Guidelines 기준으로 훑어 나온 결함을 다룬다. 대상은 개별 화면이 아니라 **공용 프리미티브 4개**(`index.css`의 `@theme`, `Sheet`, `form`, `SegmentedTabs`)다. 여기를 고치면 소비자 화면 29개가 함께 낫는다.

제약: 화면 디자인의 1차 기준은 `docs/design-mockup-v2.html`(로컬 전용)이다. **목업의 인상을 바꾸는 결정은 이 change의 범위 밖**이며, 대비 미달을 고치되 비비드한 성격은 유지해야 한다.

## Decisions

### D1. 색 토큰을 면(surface)과 글씨(ink)로 이원화한다

세 안을 실물 컴포넌트로 나란히 그려 비교한 뒤 골랐다.

| | 방식 | 결과 |
| --- | --- | --- |
| 가 | 면은 밝게, 글씨만 어둡게 | AA 통과 + 인상 유지 · **채택** |
| 나 | 토큰 자체를 어두운 값으로 전면 교체 | AA 통과 · 막대·버튼·아이콘까지 어두워져 인상 손실 |
| 다 | 색은 그대로, 나머지만 수정 | 가장 넓게 쓰이는 결함이 남음 |

**근거**: WCAG 대비 기준은 **텍스트에만** 적용된다. 진행 막대·버튼 바탕·아이콘 면 같은 큰 면은 애초에 이 기준의 대상이 아니다. 그러니 면까지 어둡게 만드는 건 얻는 것 없이 목업의 성격만 잃는 선택이다.

**비용**: 토큰이 늘어난다. 대신 "언제 어느 쪽을 쓰는가"가 이름에 드러나 오용이 줄어든다.

```css
/* 면 — 목업 v2 값 그대로 */
--color-carb: #f59e0b;
--color-protein: #ef4444;
--color-fat: #06b6d4;
--color-brand: #ff6b00;

/* 글씨 — 실제 쓰이는 배경(흰 면·soft 배경) 위에서 AA를 만족하는 짝.
   최종 값과 그 근거는 아래 "구현 이탈"을 볼 것 — 설계 단계의 값 여럿이 미달이었다 */
--color-carb-ink: #b45309;
--color-protein-ink: #b91c1c;
--color-fat-ink: #0e7490;
--color-brand-ink: #e05e00;   /* 유일하게 AA 미달 — 의도된 예외 */
```

`-ink` 접미를 쓴다(`-text`·`-dark`가 아니라) — 기존 `--color-ink`(본문 먹색)와 같은 계열임이 드러나고, 이미 있는 `--color-brand-dark`(hover용 진한 면)와 헷갈리지 않는다.

### D2. `muted`는 짝을 만들지 않고 값을 올린다

`--color-muted: #94a3b8` → `#64748b` (2.56 → 4.76).

**근거**: `muted`는 보조 **텍스트** 전용 토큰이라 면으로 쓰이는 자리가 없다. 짝을 만들면 항상 한쪽만 쓰이는 죽은 토큰이 생긴다. 인상 변화도 slate-400 → slate-500 한 칸이라 거의 감지되지 않는다.

⚠️ `bg-border text-muted`(비활성 카운트 배지)는 **글씨만 고쳐서는 안 된다.** `#64748b` on `#e2e8f0`가 3.86:1로 여전히 미달이다. 이 자리만 배경을 `--color-track`(`#eef1f6`)으로 낮춰 4.5:1을 넘긴다. 색 두 개를 함께 움직여야 하는 유일한 지점이다.

### D3. 세그먼트 탭에서 tabs 패턴을 걷어낸다

`role="tablist"`/`role="tab"`을 `aria-pressed` 버튼으로 바꾼다.

**근거**: ARIA tabs 패턴은 `aria-controls`로 패널을 가리키고 좌우 화살표로 이동하는 것까지가 한 세트다. 지금 컨트롤은 **패널을 전환하지 않는다** — 같은 목록을 끼니로 거르는 필터다. 반만 구현된 상태에서는 스크린리더가 "탭 3/5"라고 안내하고 사용자가 화살표를 눌러도 아무 일이 없다. **잘못된 안내는 안내가 없는 것보다 나쁘다.**

화살표 이동을 붙여 tabs를 완성하는 길도 있으나, 필터에 tabs 의미를 씌우는 것 자체가 틀렸으므로 택하지 않는다.

### D4. 딤은 버튼이 아니라 그냥 면으로 둔다

지금은 화면 전체를 덮는 `<button aria-label="닫기">`다. 마우스로 배경을 눌러 닫는 편의를 위한 것인데, 그 대가로 **키보드 첫 탭 정지점이 거대한 닫기 버튼**이 되고 스크린리더도 이를 읽는다.

`<div onClick>` + `aria-hidden`으로 바꾸고, 닫기는 **시트 안의 실제 닫기 버튼**이 담당한다. 마우스 사용자의 배경 클릭은 그대로 동작한다.

> 일반적으로 `<div onClick>`은 금기지만(키보드로 못 누름), 여기서는 **키보드 경로가 시트 안에 따로 있는 보조 수단**이라 예외가 성립한다. 이 예외는 `Sheet` 안에서만 허용한다.

### D5. 포커스 트랩은 직접 구현한다

라이브러리(`focus-trap-react`, Radix Dialog)를 넣지 않는다.

**근거**: 시트는 `Sheet` 하나뿐이고 구조가 단순하다. 의존성 하나를 늘리는 비용이 30줄 남짓의 훅보다 크다. `<dialog>` 네이티브 요소도 후보였으나 바텀시트 애니메이션·`max-h` 제어와 스타일 재정의 비용이 커서 택하지 않았다.

`useDialog` 훅 하나로 묶는다 — 열 때 포커스 이동, Esc 닫기, Tab 순환, 닫을 때 포커스 복귀, 배경 스크롤 잠금.

### D6. 대비는 테스트로 못 박는다

토큰 값과 대비 기준을 **단위 테스트**로 검증한다(`index.css`를 파싱하는 대신, 토큰 상수를 TS로 노출하고 그 값에 대해 대비를 계산).

**근거**: 색은 눈으로 검토하면 반드시 다시 새어 들어온다. "이 토큰들은 흰 배경에서 4.5:1 이상"을 실행 가능한 명제로 남겨야 다음 사람이 밝은 값을 텍스트에 쓰는 걸 막을 수 있다. 대비 계산은 순수 함수라 TDD 대상이다(AGENTS.md).

## Risks / Trade-offs

- **토큰이 늘어 오용 가능성이 생긴다** — `text-carb`(면용)를 글씨에 쓰면 여전히 미달이다. → D6의 테스트가 값은 지켜주지만 **사용처까지는 못 막는다.** `frontend/DESIGN.md`에 규칙을 적고, 향후 `/web-design-guidelines` 검토에서 잡는다. 완전한 방어는 아니며, 이 한계를 인지하고 받아들인다.
- **`muted` 변경이 앱 전역에 퍼진다** — 보조 텍스트 색이 한 칸 진해지는 변화가 모든 화면에 걸린다. 회귀 테스트로는 잡히지 않고 눈으로 확인해야 한다.
- **포커스 트랩 자체 구현** — 라이브러리보다 엣지 케이스(동적으로 추가되는 포커스 가능 요소, 중첩 시트)에 약하다. 현재 시트가 중첩되는 경로는 없으나, 생기면 훅을 재검토해야 한다.
- **44px 터치 대상** — 끼니 세그먼트 5개를 44px 높이로 키우면 화면 위쪽을 꽤 먹는다. 시각 크기는 두고 **히트 영역만** 넓히는 쪽으로 간다(패딩·의사요소).

## 구현 이탈

설계와 다르게 간 결정들. 대부분 **테스트를 먼저 쓴 덕에 드러났다.**

### D1 값 정정 — `protein-ink`·`success`를 700 단계로 더 내렸다

D1에 적은 `--color-protein-ink: #dc2626`은 흰 배경(4.83)은 넘지만 **`protein-soft` 위에서 3.95로 미달**이었다. 매크로 칩이 바로 그 조합(soft 배경 + 같은 계열 글씨)이라 실제 사용처에서 깨진다. red-700 `#b91c1c`(5.30)으로 내렸다.

`--color-success`도 같은 이유로 `#059669` → emerald-700 `#047857`이다(`success-soft` 위 3.58 → 5.21).

둘 다 **PAIRS에 "soft 배경 위" 조합을 넣은 덕에 드러났다.** 흰 배경만 검사했으면 통과하고 넘어갔을 것이다.

### D2 정정 — 카운트 배지 배경은 손대지 않았다

설계에서는 `muted`를 `#64748b`로 올려도 `border`(`#e2e8f0`) 위에서 3.86:1이라 배경까지 낮춰야 한다고 봤다. 그런데 `#64748b`는 **`track`(`#eef1f6`) 위에서도 4.20으로 미달**이었고 — 비활성 세그먼트 라벨이 거기 올라간다 — 이를 잡으려고 `#5b6878`로 더 내리자 `border` 위에서도 4.61이 나왔다. 배경을 건드릴 이유가 사라졌다.

`#5b6878`은 Tailwind 색상표에 없는 값이다. slate-600(`#475569`)은 통과하지만 본문 먹색과 가까워져 1·2차 텍스트의 위계가 무너진다.

### D1 보강 — 브랜드 버튼의 흰 글씨는 예외로 남긴다

"면은 대비 기준의 대상이 아니다"라는 D1의 전제에 **버튼이 빠져 있었다.** 버튼은 면이면서 그 위에 글씨가 있다. `#ff6b00` 위 흰 글씨는 2.86:1이고, 큰 글씨 완화 기준(3:1)에도 못 미쳐 폰트를 키워도 해결되지 않는다.

통과하는 대안(`#c94d00` 4.62 · `#c2410c` 5.18 · 먹색 글씨 6.25)을 실물 컴포넌트로 비교한 뒤, **브랜드 색을 서비스 정체성으로 보고 현재 값을 유지하기로 했다**(2026-08-13 결정). 주요 CTA·FAB·활성 배지가 AA 미달로 남는다는 뜻이며, 이를 `tokens.ts`의 `KNOWN_EXCEPTIONS`에 적고 테스트가 그 목록을 검증한다. 예외를 늘리려면 그 파일을 고쳐야 하므로 변경이 리뷰에 드러난다.

### D4 보강 — 닫기 버튼을 `Sheet`가 직접 제공한다

딤을 탭 대상에서 빼면서 확인해보니 **`ProfileEditSheet`·`FoodQuantitySheet`·`FoodDraftSheet`에는 닫기 수단이 아예 없었다.** 딤이 유일한 닫기 경로였다. 호출측에 맡기면 또 빠뜨리므로 `Sheet`가 오른쪽 위 닫기 버튼을 직접 렌더한다(44px 히트 영역). `AnalysisResultSheet`의 자체 "닫기"는 중복이 되어 제거했다.

덤으로 `ItemEditSheet`가 `Sheet`를 쓰지 않고 껍데기를 따로 만들어 **같은 결함을 그대로 갖고 있었다.** `Sheet`로 통합했다.

### D5 보강 — 가시성 판정에 `offsetParent`를 쓰지 않는다

포커스 대상을 고를 때 처음에는 `offsetParent !== null`로 숨은 요소를 걸렀다. 그런데 이 값은 **`position: fixed` 요소에서 null**이고 레이아웃을 계산하지 않는 테스트 환경에서는 **항상 null**이라 "전부 숨김"으로 읽힌다. 첫 포커스 테스트가 이를 잡았다. `getComputedStyle`의 `display`·`visibility`로 바꿨다.

### D1 재조정 — 브랜드 글씨도 예외로 두고 `#e05e00`에서 멈췄다

적용 화면을 보고 "선택된 라벨 색이 더 밝았으면 좋겠다"는 요청이 왔다. 계산해보니 **밝기에 천장이 있었다** — 브랜드 색조(H≈25°)를 유지한 채 흰 배경 4.5:1을 지키는 가장 밝은 값이 `#b84d00`(V=72%)이고, 한 칸만 더 밝아도 4.15로 미달한다. 처음 고른 orange-700(`#c2410c`)이 이미 그 천장에 붙어 있었다.

중간에 두 가지를 시도했다가 되돌렸다.

- 색조를 순수 오렌지(`#b84d00`)로 교정 — 밝기가 같아 체감 개선이 작았다
- 선택된 세그먼트 배경을 `brand-soft`로 — 면은 밝아지지만 원하던 변화가 아니었다

최종적으로 **브랜드 글씨도 AA 예외로 두기로 했다.** `#e05e00`은 `#ff6b00`의 색조를 그대로 두고 명도만 12% 내린 값으로, 밝은 면들 위에서 3.21~3.64:1이다. AA는 아니지만 원래 값(2.52~2.86)보다는 낫고, 브랜드 인상을 지킨다.

**결과적으로 브랜드 색 계열 전체가 예외가 됐다**(면 위 흰 글씨 + 브랜드 글씨). 브랜드 색 밖의 조합 — 본문·보조 텍스트·매크로 — 은 예외 없이 AA를 지킨다. 예외는 `KNOWN_EXCEPTIONS`에 실제 수치와 함께 적었고, 테스트가 "이 목록의 조합은 정말로 미달인가"와 "PAIRS와 겹치지 않는가"를 검증한다.

교훈: 대비 기준과 브랜드 정체성이 부딪힐 때 **몰래 넘어가지 않는 것**이 최선이다. 어긴 자리를 목록으로 남기고 테스트가 지키게 하면, 나중에 누가 예외를 늘릴 때 리뷰에 드러난다.

### 범위 확장 — 포커스 표시는 앱 전체에 적용했다

proposal은 영향 코드를 `ui/`·`features/meal/`·`shell/`로 적었지만, `outline-none`이 체중·온보딩·위저드·코치 화면에도 5곳 있었다. 스펙이 "모든 상호작용 요소"를 요구하는데 일부만 고치면 **고쳤다는 말 자체가 거짓이 된다.** 같은 한 줄 패턴이라 함께 고쳤다.
