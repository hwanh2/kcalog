# meal-item-analysis (delta)

## MODIFIED Requirements

### Requirement: 음식별 분석 출력
시스템은 사진·설명 분석 결과를 **음식 항목 배열**로 반환해야 한다(SHALL). 각 항목은 이름·칼로리·탄수화물·단백질·지방을 가져야 하며(MUST), **섭취량(수량과 단위)** 을 함께 가져야 한다(MUST). 사진이 있는 분석은 항목마다 이미지 정규화 좌표(0~1)의 위치 박스를 포함해야 하고(MUST), 사진이 없는 분석은 위치 박스를 포함하지 않아야 한다(MUST NOT). 합계는 클라이언트가 항목 합으로 계산해야 한다(MUST — 응답에 총량 필드를 두지 않는다). 음식이 식별되지 않으면 빈 항목 배열과 사유를 반환해야 한다(MUST).

섭취량은 **수정 가능한 추정치**로 제시해야 하며(MUST), 사용자가 수량을 고치면 영양값을 비례 재계산할 수 있어야 한다(SHALL).

#### Scenario: 여러 음식 분석
- **WHEN** 회원이 여러 음식이 담긴 사진을 분석하면
- **THEN** 음식별 이름·영양값·섭취량·위치 박스가 항목 배열로 반환된다

#### Scenario: 섭취량 표시
- **WHEN** 분석 결과에 "닭가슴살 구이 180g 185kcal"이 포함되면
- **THEN** 확인 화면에 수량·단위가 함께 표시되고 사용자가 수정할 수 있다

#### Scenario: 설명만 분석
- **WHEN** 회원이 사진 없이 "김밥 한 줄"로 분석하면
- **THEN** 위치 박스 없이 이름·영양값·섭취량을 가진 항목이 반환된다

#### Scenario: 음식 미검출
- **WHEN** 사진에서 음식이 식별되지 않으면
- **THEN** 빈 항목 배열과 사유가 반환된다

### Requirement: 음식별 수정과 합계 자동 재계산
프론트엔드는 각 음식 항목의 이름·영양값·**수량**을 수정할 수 있게 해야 한다(SHALL). 수량을 수정하면 그 항목의 영양값을 기준 수량 대비 비례 계산해 갱신해야 하며(MUST), 항목이 바뀔 때마다 식사 합계를 즉시 재계산해 표시해야 한다(MUST). 항목을 추가·삭제할 수 있어야 한다(SHALL).

#### Scenario: 수량 수정
- **WHEN** 회원이 "현미밥 150g 210kcal"의 수량을 100g으로 고치면
- **THEN** 영양값이 비례해 재계산되고 합계가 즉시 갱신된다

#### Scenario: 항목 수정 시 합계 갱신
- **WHEN** 회원이 항목의 칼로리를 직접 고치면
- **THEN** 입력한 값이 그대로 쓰이고 합계가 즉시 갱신된다

#### Scenario: 항목 추가·삭제
- **WHEN** 회원이 잘못 인식된 항목을 삭제하거나 빠진 음식을 직접 추가하면
- **THEN** 목록에서 제거·추가되고 합계가 즉시 갱신된다
