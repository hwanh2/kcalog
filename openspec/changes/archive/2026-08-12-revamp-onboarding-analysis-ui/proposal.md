# revamp-onboarding-analysis-ui

## Why

앱의 첫 인상(온보딩)과 핵심 흐름(사진 분석 확인)이 아직 개발용 화면에 가깝다. 온보딩은 "온보딩" 제목 아래 6개 입력을 한 번에 요구해 이탈 부담이 크고, 계산의 근거인 유지칼로리(TDEE)를 내부에서만 쓰고 버려 "왜 이 목표인지"가 보이지 않는다. 사진 분석 확인 화면은 합계가 한 줄 텍스트라 무엇이 얼마인지 훑기 어렵다.

또한 목표 체중을 필수로 받는 탓에 **기록만 하려는 사용자**가 진입할 수 없다. 목표는 방향(감량/유지/증량)만 받고 목표 체중은 선택으로 낮춘다.

## What Changes

- **단계별 온보딩 위저드** — 한 화면 6개 입력에서 5단계(성별 → 키·몸무게·나이 → 활동량 → 목표 → 완료 플랜)로 전환. 단계마다 질문 하나, 진행 표시, 하단 고정 CTA.
- **목표를 방향으로 입력** — 목표 체중(kg) 필수에서 **목표 방향(감량/유지/증량)** 선택으로. 목표 체중은 감량·증량을 고른 경우에만 **선택 입력**. 방향을 회원 정보로 저장해, 목표 체중이 없어도 추천 목표를 낼 수 있다.
- **활동량 4단계** — 거의 앉아서 생활 / 보통 / 활동적 / 매우 활동적. 기존 3단계에 매우 활동적을 추가하고 문구를 "주 N회 운동"으로 구체화.
- **완료 화면에 근거 노출** — 유지칼로리(TDEE)와 목표 섭취량, 탄단지 목표를 함께 보여준다(현재는 목표 kcal 한 줄).
- **사진 분석 확인 화면 정리** — 분석 요약 카드(음식 수·총 kcal·탄단지)와 항목 리스트를 오버레이 모드에서도 함께 표시. 저장 버튼에 끼니를 반영.
- **UI** — 목업 흐름을 따르되 시각 언어는 현재 앱(brand 오렌지·Card·Button 토큰)에 맞춘다.

## Impact

- Affected specs: `onboarding` (수정), `meal-item-analysis` (수정)
- Affected code (backend): `Goal` enum 신설, `Member.goal` 컬럼(Flyway **V12**), `ActivityLevel`에 `VERY_HIGH` 추가, `DailyKcalCalculator.toTarget`을 목표 방향 기반으로, `OnboardingRequest`(목표 체중 선택·목표 방향 필수), `KcalSuggestionResponse`에 유지칼로리·탄단지 목표 추가, `TdeeService` 추천 목표를 방향 기반으로
- Affected code (frontend): `OnboardingPage` 5단계 위저드로 재작성, `api/member.ts` 타입, `MealRecordPage` 요약 카드·항목 리스트, `ProfilePage` 활동량 4단계·목표 방향
- 마이그레이션: V12 (`member.goal`)
- 스코프 밖: 항목별 신뢰도·양(g) 도입(분석 응답에 데이터 없음 — 별도 change), 온보딩 건너뛰기, 목표 체중 없이 완료 판정 변경
