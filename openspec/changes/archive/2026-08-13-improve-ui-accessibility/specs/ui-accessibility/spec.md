# ui-accessibility (delta)

## ADDED Requirements

### Requirement: 텍스트 색 대비

화면의 모든 텍스트는 배경과 **WCAG AA 대비**를 만족해야 한다(MUST) — 본문 4.5:1 이상, 18pt(24px) 이상이거나 14pt(18.66px) 이상 굵은 글씨는 3:1 이상.

색 토큰은 **면(surface)용과 글씨(ink)용을 분리해야 한다**(MUST). 배경·진행 막대·버튼 바탕·아이콘 면처럼 대비 기준이 걸리지 않는 곳은 밝은 값을 유지하고, 같은 색 계열을 글씨로 쓸 때는 어두운 짝을 써야 한다. 이 분리는 `index.css`의 `@theme` 한 곳에서만 정의해야 한다(MUST).

#### Scenario: 보조 텍스트 대비
- **WHEN** 기록 목록의 "150g · 오전 8:20" 같은 보조 텍스트를 흰 카드 위에 그리면
- **THEN** 그 색과 배경의 대비가 4.5:1 이상이다

#### Scenario: 매크로 값 텍스트
- **WHEN** 매크로 칩·사진 배지에 "탄 45" 같은 작은 글씨를 색으로 구분해 그리면
- **THEN** 각 매크로 색의 **글씨용 짝**이 쓰이고 배경과 4.5:1 이상을 만족한다

#### Scenario: 면은 밝게 유지
- **WHEN** 같은 매크로 색을 진행 막대·칩 배경·버튼 바탕처럼 면으로 쓰면
- **THEN** 목업 v2의 밝은 값이 그대로 쓰인다(대비 기준이 걸리지 않는 용도)

#### Scenario: 색 두 개를 함께 조정해야 하는 경우
- **WHEN** 회색 배경 위 회색 글씨처럼 글씨만 어둡게 해서는 4.5:1에 닿지 않으면
- **THEN** 배경 값도 함께 낮춰 기준을 만족시킨다

### Requirement: 키보드 조작과 포커스 표시

모든 상호작용 요소는 키보드만으로 도달·조작할 수 있어야 한다(MUST). 포커스에는 **눈에 보이는 표시**가 있어야 하며(MUST), 1px 테두리 색 변경만으로 대신해서는 안 된다(MUST NOT).

포커스 표시는 `focus-visible`을 기준으로 해야 한다(MUST) — 마우스 클릭에는 나타나지 않고 키보드 이동에는 나타나야 한다.

#### Scenario: 입력 필드 포커스
- **WHEN** 사용자가 탭으로 입력 필드에 도달하면
- **THEN** 배경과 뚜렷이 구분되는 포커스 링이 나타난다

#### Scenario: 마우스 클릭
- **WHEN** 사용자가 같은 입력 필드를 마우스로 클릭하면
- **THEN** 포커스 링이 나타나지 않는다

### Requirement: 바텀시트의 다이얼로그 규약

`aria-modal`을 선언한 시트는 다음을 모두 지켜야 한다(MUST).

- 열릴 때 포커스를 시트 안으로 옮긴다
- **Esc**로 닫힌다
- 탭 순서가 시트 안에 갇힌다(뒤 배경으로 새지 않는다)
- 닫힐 때 포커스를 열기 전 요소로 되돌린다
- 열려 있는 동안 뒤 배경이 스크롤되지 않는다

배경 딤은 눌러서 닫을 수 있어야 하지만(SHALL), **키보드 탭 정지점이나 스크린리더 읽기 대상이 되어서는 안 된다**(MUST NOT) — 닫기 수단은 시트 안에 따로 있어야 한다.

#### Scenario: Esc로 닫기
- **WHEN** 수량 조절 시트가 열린 상태에서 Esc를 누르면
- **THEN** 시트가 닫히고 포커스가 시트를 연 버튼으로 돌아간다

#### Scenario: 포커스 가둠
- **WHEN** 시트가 열린 상태에서 탭을 계속 누르면
- **THEN** 포커스가 시트 안 요소들만 순환하고 뒤 화면으로 나가지 않는다

#### Scenario: 딤은 탭 대상이 아니다
- **WHEN** 스크린리더가 시트를 읽으면
- **THEN** 화면을 덮는 "닫기" 버튼이 읽히지 않고, 시트 안의 닫기 수단만 노출된다

#### Scenario: 배경 스크롤 잠금
- **WHEN** 시트가 열린 상태에서 시트 내용을 끝까지 스크롤하고 계속 밀면
- **THEN** 뒤 페이지가 함께 스크롤되지 않는다

### Requirement: 상태 전환 컨트롤의 ARIA

목록을 거르는 세그먼트 컨트롤은 **tabs 패턴(`role="tab"`)을 쓰지 않아야 한다**(MUST NOT) — 패널을 전환하지 않으므로 `aria-controls`·화살표 키 이동을 갖출 수 없고, 반만 구현하면 스크린리더가 없는 동작을 안내하게 된다. 대신 `aria-pressed`를 쓴 버튼으로 선택 상태를 알려야 한다(MUST).

아이콘만 있는 버튼에는 `aria-label`이 있어야 하고(MUST), 텍스트 라벨이 함께 있는 아이콘은 `aria-hidden`이어야 한다(MUST).

#### Scenario: 끼니 세그먼트 선택 상태
- **WHEN** 스크린리더가 "아침" 세그먼트에 도달하면
- **THEN** 버튼으로 읽히고 선택 여부가 눌림 상태로 안내된다

### Requirement: 오류 알림

실패·제한 초과처럼 **사용자가 놓치면 안 되는 안내**는 `role="alert"`로 즉시 알리고 오류 색으로 표시해야 한다(MUST). 진행·성공 안내에만 `role="status"`를 쓴다(SHALL).

#### Scenario: 분석 실패 안내
- **WHEN** AI 분석이 실패하거나 일일 횟수를 초과해 안내가 뜨면
- **THEN** 스크린리더가 즉시 읽어주고, 보조 텍스트가 아닌 오류 색으로 표시된다

### Requirement: 모바일 터치와 안전 영역

터치 대상은 **최소 44×44px**여야 한다(MUST). 시각적으로 더 작아야 하면 히트 영역을 넓혀 기준을 맞춘다.

화면 아래에 고정되는 요소(하단 내비, 바텀시트의 동작 버튼)는 `env(safe-area-inset-bottom)`을 반영해야 한다(MUST). 탭이 잦은 영역에는 `touch-action: manipulation`을 적용해 더블탭 확대 지연을 없애야 한다(MUST).

#### Scenario: 바텀시트의 안전 영역
- **WHEN** 노치가 있는 기기에서 바텀시트를 열면
- **THEN** 시트 하단의 버튼이 홈 인디케이터에 가리지 않는다

#### Scenario: 탭 지연 없음
- **WHEN** 사용자가 끼니 세그먼트를 연달아 빠르게 누르면
- **THEN** 확대 판정을 기다리는 지연 없이 즉시 전환된다

### Requirement: 문서 언어와 앱 메타

문서 루트의 `lang`은 실제 콘텐츠 언어와 일치해야 한다(MUST). PWA 셸은 배경색과 일치하는 `theme-color`를 선언해야 하고(SHALL), 문서 제목은 서비스명을 담아야 한다(SHALL).

#### Scenario: 한국어 문서 선언
- **WHEN** 스크린리더가 페이지를 읽으면
- **THEN** 한국어로 인식해 읽는다

### Requirement: 모션 축소 존중

움직이는 표현은 `prefers-reduced-motion: reduce`에서 멈추거나 축소 변형을 제공해야 한다(MUST). 애니메이션은 `transform`·`opacity`로 한정해야 하며(SHALL), `transition: all`을 쓰지 않아야 한다(MUST NOT).

#### Scenario: 분석 중 스캔 애니메이션
- **WHEN** 모션 축소를 켠 사용자가 분석 대기 화면을 보면
- **THEN** 스캔 라인과 맥동이 멈추고 정지 상태로 표시된다
